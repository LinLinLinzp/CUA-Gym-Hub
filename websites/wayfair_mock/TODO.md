Use this port for preview too, after stopping the dev listener. Keep any test runner scratch files in a gitignored directory such as `test-results/`, or remove them after execution.
- [x] **Account shell and all routes.** Build the 72 px header, 232 px desktop rail and responsive one-column layout in [DESIGN.md](DESIGN.md). `/` is the account overview. Implement `/orders`, `/orders/:orderId`, `/deliveries`, `/deliveries/:shipmentId`, `/claims`, `/claims/:claimId`, `/returns` and `/returns/:returnId`. Put the store, toast and any theme provider above the entire route tree. Show a recovery link for unknown routes and missing records. Keep `sid` across internal routing and browser back/forward, including redirects, breadcrumbs, and history links. Use the template's `withSid()` for internal links outside the SPA router. Set the title to `Wayfair | My Account`.
- [x] **State bootstrap and endpoints.** Copy `templates/dataManager.js` byte-for-byte into `src/utils/dataManager.js`. Import `stateApi` from `../../templates/state-api.js` in `vite.config.js` and pass `createInitialData` from `src/data/seed.js`. Before rendering routes, display neutral loading and await `loadState('wayfair_mock', createInitialData)`. Use the template's JSON `GET /state`, `POST /post`, and `GET /go` in dev and preview. In the built Harbor site, those paths are provided by the host. `GET /go` must yield `initial_state`, `current_state` and `state_diff`.
- [x] **State writes and injection.** Centralize mutation and persistence in the store. Each successful confirmation applies one atomic business mutation and calls `saveState('wayfair_mock', nextState)` once with the complete JSON state. Revalidate against current store state at confirmation. Guard repeated submit events and retain unknown injected fields. Keep drafts, previews, active tabs, filters, sorting and pagination in UI or query state. After bootstrap, idle tabs and route loads write nothing. Render injected empty arrays, single records, hundreds of records, and missing optional fields or unresolved links. Derive dates and eligibility using `new Date()` and use ISO timestamps for each new business action.
- [x] **Seed, local assets and verifier documentation.** Implement the seed plan below and the exact shapes and transitions in the [state model](assets/data_model.md). Use English synthetic data and original local furniture art. The sidebar, all product art, and all interactions must work offline with system fonts or locally bundled fonts. Create `SCHEMA.md` with every top-level key and nested shape, plus an **Observable State Changes** table matching the code. Store derived metrics and labels in the view layer.

## P1 — Required workflows

- [x] **Orders.** On the overview, link recent orders, the next scheduled delivery and open service requests. On `/orders`, search case-insensitively by order number, product name or SKU. Filter by order status and by year, sort newest or oldest, and page 12 results at a time. Preserve controls on return from detail. Order cards show date, number, total, product previews and current status. Order detail shows line quantities, payment summary, ship-to address and separate shipment tracking timelines. For unshipped lines, offer **Cancel items**, with line selection, one or more whole units per line, reason, estimated credit and confirmation. Show an order-level cancellation status derived from item quantities and fulfillment. **Writes** `orderCancellations[]` (`id`, `orderId`, `status`, `reason`, `items[]` with `orderItemId`, `quantity` and `estimatedCredit`, `estimatedCredit`, `currency`, `actorId`, `createdAt`) and increments the selected `orders[].items[].canceledQuantity` in the same save. Order navigation and tracking are read-only.
- [x] **Delivery scheduling.** On `/deliveries`, show future confirmed appointments first, followed by shipments that can be scheduled. Provide an all-deliveries filter and link each result to shipment detail. From that detail or the corresponding order, offer **Schedule delivery** or **Reschedule delivery** for a freight shipment ready to book. Show local dates and time windows, the existing appointment if present, address, and optional delivery instructions. Review and confirm a slot. Provide **Cancel appointment** with confirmation for a future active booking, then allow a new booking. Show parcel tracking, past appointments and a no-slots state where applicable. **Writes** a `deliveryAppointments[]` record (`id`, `orderId`, `shipmentId`, `slotId`, `startAt`, `endAt`, `timeZone`, `instructions`, `status`, `actorId`, `createdAt`, optional `previousAppointmentId`). Rescheduling also sets the old record's `status`, `updatedAt`, `updatedBy` and `replacedByAppointmentId`. Cancellation sets the active record's `status`, `updatedAt`, `updatedBy` and `canceledAt`. Derive delivery status from these records and the original shipment.
- [x] **Damage claims.** From a delivered order line or **Report damage** on `/claims`, select an order, one eligible item, quantity, issue type, description and preferred resolution. Offer up to three optional local JPEG or PNG files with filename, remove control, and size/type validation. Review and confirm. Open the claim detail immediately and show the claim reference, requested resolution and current status. Link it from both the claims list and affected order. Provide status filters and retain claim history. **Writes** `damageClaims[]` (`id`, `orderId`, `orderItemId`, `shipmentId`, `quantity`, `issueType`, `description`, `requestedResolution`, `attachments[]` metadata, `status`, `actorId`, `createdAt`). Reserve affected quantity against further claims and returns as specified in the [state model](assets/data_model.md).
- [x] **Returns.** From an order or `/returns`, start a return, select one or more eligible delivered lines in the same order, enter quantity and reason per line, and select a compatible handoff and refund method. Show the estimated item refund, fee and net refund on review. On confirmation, show a reference, handoff instructions and the refund summary. Add a history entry and an order detail link. Allow a requested return to be canceled after confirmation. When applicable, show the final-sale, window-expired, mixed-handoff or quantity restriction beside the relevant choice. **Writes** `returns[]` (`id`, `orderId`, `items[]` with `orderItemId`, `quantity`, `reason` and `refundAmount`, `handoffMethod`, `refundMethod`, `refundSubtotal`, `returnFee`, `estimatedRefund`, `currency`, `status`, `actorId`, `createdAt`). Cancellation sets that record's `status`, `updatedAt`, `updatedBy` and `canceledAt` and releases its reserved quantities.

## Scope

The account starts signed in as the synthetic account holder, Ava Morgan. The interface covers post-purchase order management, delivery scheduling, damage claims and returns. Storefront browsing, checkout, authentication, real payment processing, notifications to external services, and production account access are outside this implementation. Keep all changes inside `websites/wayfair_mock` and leave committing and pushing to the user.
