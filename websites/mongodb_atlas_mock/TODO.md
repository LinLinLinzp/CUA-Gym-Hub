## P1 — SEED workflows

Each successful mutation updates the entity and appends exactly one structured `activityLog` entry in the same save. The [state model](assets/data_model.md) gives the event actions and field-level contract.

- [x] **Clusters — browse and deploy.** Table columns show name, tier, provider/region, version and state. Search by name, filter tier/status, and open detail by name. **Create cluster** selects Free, Flex or Dedicated, a supported provider/region pair, the tier, and a project-unique name. Show an editable review before deploying. Save a `clusters[]` record with `id, projectId, name, provider, region, tier, mongoVersion, diskSizeGB, backupEnabled, terminationProtection, status: "active"` and creation/update metadata. Append `cluster.created`.
- [x] **Clusters — edit, pause, resume and terminate.** Detail exposes settings and a named actions menu. Review changes to supported settings (dedicated sizing, backup and termination protection) before applying. Pause an active dedicated cluster and resume a paused dedicated cluster through confirmation. Disable configuration edits while paused. Require the exact cluster name to terminate and honor termination protection. Edit updates changed config fields, pause/resume update `status`, and termination records `status: "terminated"` plus `terminatedAt` and hides the row from active inventory. All update `updatedAt, updatedBy`. Append `cluster.updated`, `cluster.paused`, `cluster.resumed` or `cluster.terminated`. Keep the same id throughout.
- [x] **Users — database user access.** Show username, roles, cluster scope, expiry and status. Search by username and filter by role/status. **Add database user** takes a project-unique username, a masked synthetic credential, roles and optional cluster restrictions or 6-hour/1-day/1-week expiry. Edit role and scope assignments and temporary settings. Confirm Delete and release the username from active uniqueness. Save `databaseUsers[]` with `id, projectId, username, authMethod, authDatabase, roles, clusterIds, expiresAt, status` and creation/update metadata. On edit write changed roles/scope/expiry and update metadata. On delete save `status: "deleted", deletedAt, updatedAt, updatedBy`. Append `database_user.created`, `database_user.updated` or `database_user.deleted`. Keep password input in form memory and clear it when the form closes.
- [x] **Users — project identity and access.** From Project Access, search the project roster by email/name, filter by role or status, and use **Grant access** with an email and one or more project roles. Mark an existing organization member active and an external address pending. Allow role changes and confirmed removal or invitation cancellation. Save `projectUsers[]` with `id, projectId, email, name?, roles, status, invitedAt?, expiresAt?` and creation/update metadata. Subsequent changes save `roles` or `status: "removed", removedAt` plus update metadata. Append `project_user.granted`, `project_user.invited`, `project_user.roles_updated`, `project_user.removed` or `project_user.invite_cancelled`.
- [x] **Network access — IP access list.** List address/CIDR, comment, status and expiry. Search address/comment and filter active/temporary/expired entries. **Add IP address** accepts an IPv4 address or CIDR, optional comment and optional 6-hour/1-day/1-week duration, with inline format and duplicate validation. Confirm address/comment edits and support temporary duration changes or conversion to permanent. Confirm deletion. Save `ipAccessList[]` with `id, projectId, address, comment, expiresAt, status` and creation/update metadata. Edits update changed fields and update metadata. Delete writes `status: "deleted", deletedAt, updatedAt, updatedBy`. Append `ip_access.created`, `ip_access.updated` or `ip_access.deleted`. Expired entries are derived from the clock without a write.
- [x] **Release evidence.** Write `SCHEMA.md` for all shipped keys and actual observable writes. Run `npm run build` and Chromium on localhost:5487. For each SEED workflow, follow the UI end-to-end and check the exact changed records through `/go?sid=...`. Cover invalid/cancelled input, hard reload, session isolation, injected sparse worlds and idle POST count. Record cases, observed fields and results in `TEST.md`. Use gitignored scratch or remove test scratch afterward. The parent runner handles Docker certification and commits.
