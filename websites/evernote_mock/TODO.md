## P1 — Seed workflows

- [x] **P1.1 Notes — browse, search and filter.** Show title, notebook, excerpt, last edit and tags in the Notes collection. Open a note from its card/row and use a link for its notebook. Search active notes by case-insensitive title, body and tag text, submit by Enter, and support a clear empty-query state. Filter by notebook and tag, show active removable filters, and sort by updated date, created date or title. Show a reset action for empty results. Opening, searching, filtering and sorting do not write state.
- [x] **P1.2 Notes — create, read and edit.** `New note` opens an editor and focuses Title. Use the current notebook from its detail page and the effective default elsewhere. If none exists, offer notebook creation inside the same flow. Persist an active `notes[]` record with `id, notebookId, title, content, tags, status, createdBy, createdAt, updatedBy, updatedAt, trashedAt, trashedBy`. Title/body edits are retained as a draft until Save, editor focus leaves the edit region, or an in-app transition leaves the editor. Show Saved after committing, keep the draft stable through re-render, and flush before opening another record or closing the editor. Save changes to `notes[].title/content/updatedBy/updatedAt`; treat no-op saves as no-ops. Empty titles display as Untitled note.
- [x] **P1.3 Notes — move, tag and duplicate.** Give each note an actions menu with Move to notebook and Duplicate, and give the editor a tag picker accepting an existing or new label. Move via a searchable active destination list and write `notes[].notebookId/updatedBy/updatedAt`. Trim tag labels, dedupe case-insensitively, and persist adds/removes in `notes[].tags/updatedBy/updatedAt`. Duplicate into the current active notebook with a fresh `notes[]` record, a ` (copy)` title suffix and `sourceNoteId`. For each non-deleted source task, persist a separate `tasks[]` copy pointing to the new note, with a fresh ID and `sourceTaskId`. Create the note and task copies atomically.
- [x] **P1.4 Notes — trash and restore.** Move to Trash hides the note from active results and its tasks from active task views. Write `notes[].status=trashed/trashedAt/trashedBy/updatedBy/updatedAt`. Trash shows the note read-only with Restore. Restore uses its original notebook when active, else the effective default. When neither exists, prompt for a new notebook before restoring. Write `notes[].status=active/notebookId/trashedAt=null/trashedBy=null/updatedBy/updatedAt`. Linked tasks reappear with their previous status and note ID. Canceling any confirmation or recovery prompt makes no writes.
- [x] **P1.5 Notebooks — create, browse and rename.** Notebook cards show name, active note count and the default marker. Include search by name, alphabetical order and a visible New notebook button. Notebook detail uses the scoped Notes collection and exposes New note and Notebook actions. A dialog validates trimmed, nonempty, case-insensitively unique active names. Creation appends `notebooks[]` with `id, name, status, createdBy, createdAt, updatedBy, updatedAt, deletedAt, deletedBy`. The first notebook in an empty world also sets `preferences.defaultNotebookId/updatedBy/updatedAt`. Rename keeps membership and changes `notebooks[].name/updatedBy/updatedAt`.
- [x] **P1.6 Notebooks — set default and delete.** Provide Set as default in Notebook actions and write `preferences.defaultNotebookId/updatedBy/updatedAt`. Creation outside a notebook uses that destination. Protect the effective default from deletion with an explanation and a way to choose a different default. Confirm deletion with the count of active notes affected. In one mutation set `notebooks[].status=deleted/deletedAt/deletedBy/updatedBy/updatedAt` and set each active child note's trash fields as in P1.4. Leave original `notebookId` references and task records in place. Exclude the deleted notebook from selection and browsing.
- [x] **P1.7 Tasks — capture and read in both views.** Provide New task in Tasks and Add task within the note editor. Require a trimmed nonempty title and offer note, description, due date and flag. In-note creation preselects that note. Account-wide creation preselects the valid default task note or offers to create/use Things to do in the effective default notebook. If the account is empty, offer a notebook name and create the notebook, fallback note, and task in one submit. Persist a new `tasks[]` record with `id, noteId, title, description, dueDate, flagged, status, completedAt, completedBy, deletedAt, deletedBy, createdBy, createdAt, updatedBy, updatedAt`. Fallback creation writes the corresponding notebook/note records and default IDs as needed. Both views render the same task ID. Use an Open note link in Tasks.
- [x] **P1.8 Tasks — edit, reprioritize, complete, reopen and delete.** Open task details in either view. Allow changing title, description, note link, date and flag. Write the changed fields in `tasks[]` and `updatedBy/updatedAt`. Both views support status toggling and update `status/completedAt/completedBy/updatedBy/updatedAt`; reopen clears completion metadata. Confirm deletion and write `status=deleted/deletedAt/deletedBy/updatedBy/updatedAt`. Group Tasks by due date or note and offer Open, Completed, All and Flagged filters. Date-only deadlines use local calendar days and the runtime clock. Provide Set default task note in Tasks and persist `preferences.defaultTaskNoteId/updatedBy/updatedAt`. Only active notes appear in the picker.
- [x] **P1.9 Browser acceptance and workflow evidence.** Use the installed Node Playwright identified by `PILOT_PLAYWRIGHT` and the installed Chromium. Test only `http://localhost:5409`. Launch a persistent server from this directory via PowerShell `Start-Process -WindowStyle Hidden` with the absolute Vite JS entry point and `--host localhost --port 5409 --strictPort`. Use separate test SIDs, including a normal seed, empty arrays, a singleton with optional fields missing, and hundreds of injected records. Check direct loads, hard reloads, SID isolation, cross-view task updates, one committed state write for compound changes, and no writes during passive navigation or a settled idle period. Assert `/go?sid=...` field values after each mutation and test one journey combining a notebook, note, and task through reload. Record actions, fields, build results and any failures in `TEST.md` during QA. The parent runner handles Docker dynamic certification and commits.
