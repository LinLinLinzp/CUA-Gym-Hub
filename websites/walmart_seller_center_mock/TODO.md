## P1 — Items, orders and returns

- [x] **Items — catalog and detail.** Search by name, SKU, item ID or product ID, filter by listing status and stock, sort by item name or update date, and paginate 15 rows. Rows show original category artwork, product name, SKU, category, price, available stock and listing status. Item detail shows content, offer, inventory and activity. This workflow reads `items` and `itemActions` and writes no records until a form is submitted.
- [x] **Items — add, edit, price, inventory and lifecycle.** Add item opens a form with name, SKU, category, brand, optional product ID and description, price, fulfillment and starting stock. Require a unique SKU (case-insensitive), a positive USD price with at most two decimal places, and nonnegative whole-number stock. Save as Draft or Publish. Detail actions edit listing content, update price, update available units at the named seller location, and confirm retire or republish. Only seller-fulfilled items have editable available stock. Keep identity and SKU stable on edit so cross-links survive. Each save inserts or patches one `items[]` record, sets `updatedAt` and `updatedBy`, and appends one `itemActions[]` record with item ID, SKU, action, actor, timestamp and changed values.
- [x] **Orders — queues and detail.** Default to Unshipped and offer Shipped, Canceled and All. Search by purchase order number, customer order number, customer name or SKU. Add ship-by and fulfillment filters. Show order identifiers, customer, line count, ship-by date, total and status. Detail shows product lines, quantities, charges, ship-to information when supplied, and fulfillment activity. Read `orders` and `orderActions`. Listing, selection and drill-down write no records.
- [x] **Orders — acknowledge.** Acknowledge a New order from its detail view or select eligible orders in Unshipped and choose Acknowledge. Set each targeted `orders[].status` and the eligible `lines[].status` to `acknowledged`, write `acknowledgedAt`, `updatedAt`, `updatedBy`, and append one `orderActions[]` record per order with linked line IDs, SKUs and quantities. Repeating confirmation leaves state unchanged.
- [x] **Orders — mark shipped or cancel.** For an acknowledged order, collect a carrier and non-empty tracking number and confirm Mark as shipped for all open lines. For New or Acknowledged orders, allow Cancel order with a required reason and confirm all open lines. Each action updates order and affected line statuses, order actor/timestamp and the corresponding shipment or cancellation timestamp. Append an `orderActions[]` record with purchase order, affected lines and quantities, and either carrier/tracking or cancellation reason. Guard terminal or ineligible orders at submission. This phase supports whole-order fulfillment and cancellation.
- [x] **Returns — queues and detail.** Provide All, In transit, Received and Refunded views. Search by return ID, purchase order ID, SKU or customer name and filter by return reason. Show return ID, linked purchase order, item summary, reason, initiated date, refund amount/status and return status. Detail presents return quantities, item-level eligibility, tracking where available and prior refunds. Read `returns`, `refunds` and related order data. Navigation and filtering write no records.
- [x] **Returns — receive and issue refund.** The local warehouse action Mark received moves an eligible in-transit return to Received, updates `returns[].receivedAt`, `updatedAt` and `updatedBy`, and appends a `returnActions[]` receipt record with line IDs and quantities. In Received, Issue refund opens a review with selectable eligible lines and quantities, calculated USD amounts and a confirmation. Update `returns[].lines[].refundedQuantity`, return totals and statuses, timestamps and actor. Append a `refunds[]` transaction with order and return IDs, per-line quantities and amounts, overall amount, status, actor and timestamp. Allow a second refund only for remaining quantities. Apply no automatic restock, refund or later transition.
