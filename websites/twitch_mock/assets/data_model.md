# Twitch workspace state model

Use plain JSON. Persist canonical data and derive presentation at render time. Identifiers are opaque strings. Date-times are ISO UTC strings, local calendar dates are `YYYY-MM-DD`, and numbers store duration and counts. Default values and fixture examples below guide implementation. `SCHEMA.md` describes the final implemented model.

## Root keys and record shapes

Optional keys are marked `?`. Nullable fields explicitly accept `null`. Preserve unknown injected keys when writing an edited entity.

| Key | Shape and example values |
| --- | --- |
| `account` | `{id, login, displayName, channelName, tier}`. Example `{id:"creator-001", login:"fieldnotelive", displayName:"Rhea Mercer", channelName:"Fieldnote Live", tier:"affiliate"}`. Strings, `id` is the active actor. |
| `moderators` | `[{id, login, displayName}]`. Example `{id:"moderator-001", login:"inkandivy", displayName:"Ivy Rowan"}`. Strings. |
| `categories` | `[{id, name, artworkKey?}]`. Example `{id:"cat-art", name:"Art", artworkKey:"printmaking"}`. Strings. `artworkKey` selects an original local cover style. |
| `streamSettings` | `{id, title, goLiveNotification, categoryId, language, tags, classificationLabels, storePastBroadcasts, alwaysPublishVods, excludedCategoryIds, updatedAt}`. Example `{id:"stream-001", title:"Late Studio: carving a two-color linocut", goLiveNotification:"The print bench is open.", categoryId:"cat-art", language:"en", tags:["Printmaking","StudioSession"], classificationLabels:[], storePastBroadcasts:true, alwaysPublishVods:false, excludedCategoryIds:["cat-music"], updatedAt:"2026-11-16T22:05:00.000Z"}`. Flags are booleans, array elements are strings, remaining fields are strings. Use stable label ids such as `significant_profanity` with human-readable UI names. |
| `videos` | `[{id, title, description?, categoryId, language, type, status, durationSeconds, viewCount, artworkKey?, createdAt, updatedAt, publishedAt, deletedAt?}]`. `type` is `past_broadcast`, `highlight` or `upload`. `status` is `published`, `unpublished` or `deleted`. Example `video-011`, “Bookbinding after hours”, `cat-makers`, `en`, `past_broadcast`, `published`, 4235 seconds, 384 views, `book-arts`, created `2026-11-13T02:00:00.000Z`, published `2026-11-13T02:08:00.000Z`. Timestamps are strings, `publishedAt` is nullable, and `deletedAt` is set only after deletion. |
| `viewers` | `[{id, login, displayName, joinedAt?, updatedAt?, restriction}]`. `restriction` is `null` or `{type, reason, startedAt, expiresAt, actionId}`. Example `viewer-009`, `clayandthread`, “Clay and Thread”, joined `2025-10-04T12:00:00.000Z`, restriction `{type:"ban", reason:"Repeated spam", startedAt:"2026-11-17T20:40:00.000Z", expiresAt:null, actionId:"mod-action-023"}`. Timeout uses `type:"timeout"` and a non-null expiry. Other values are strings. |
| `chatMessages` | `[{id, viewerId, text, createdAt, status, deletedAt?, deletedBy?}]`. Example `msg-012`, `viewer-012`, “What paper weight are you using for that edition?”, `2026-11-16T23:12:00.000Z`, `visible`. `status` is `visible` or `deleted`. `deletedBy` is the actor id. |
| `modActions` | `[{id, action, actorId, viewerId, messageId?, reason, durationSeconds?, expiresAt?, relatedActionId?, resultingStatus, createdAt}]`. `action` is `timeout`, `ban`, `unban`, `untimeout` or `delete_message`. `resultingStatus` is `timed_out`, `banned`, `clear`, or `deleted`. Example `mod-action-021`, `timeout`, `moderator-001`, `viewer-015`, “Repeated off-topic links”, 600, `2026-11-17T21:10:00.000Z`, `timed_out`, `2026-11-17T21:00:00.000Z`. For a reversal or ban following an active timeout, `relatedActionId` points to the restriction being replaced. For message deletion the reason may be empty and `messageId` is required. |
| `scheduleSettings` | `{id, timezone, vacationEnabled, vacationStartDate, vacationEndDate, updatedAt}`. Example `schedule-001`, `America/New_York`, `false`, `null`, `null`, `2026-11-16T18:00:00.000Z`. Dates are nullable local calendar strings. Vacation limits are inclusive in this timezone. |
| `scheduleEntries` | `[{id, title, categoryId, startsAt, timezone, durationMinutes, recurrence, weekday, status, createdAt, updatedAt, deletedAt?}]`. Example `slot-014`, “Friday print lab”, `cat-art`, `2026-11-20T23:30:00.000Z`, `America/New_York`, 90, `weekly`, 5, `scheduled`, and fixed ISO audit timestamps. `recurrence` is `once` or `weekly`. `weekday` is ISO 1–7 for weekly or `null` for once. `status` is `scheduled`, `cancelled`, or `deleted`. A weekly anchor starts the series. |
| `scheduleExceptions` | `[{id, entryId, occurrenceDate, status, createdAt, updatedAt}]`. Example `slot-014:2026-11-27`, `slot-014`, `2026-11-27`, `cancelled`, and fixed ISO audit timestamps. `status` is `cancelled` or `restored`. An exception refers to the calendar date in the entry timezone. |
| `stateChanges` | `[{id, action, actorId, targetType, targetId, status, changes, createdAt}]`. Example `{id:"change-001", action:"unpublish_video", actorId:"creator-001", targetType:"video", targetId:"video-011", status:"applied", changes:{status:{from:"published",to:"unpublished"},publishedAt:{from:"2026-11-13T02:08:00.000Z",to:null}}, createdAt:"2026-11-18T15:10:00.000Z"}`. `changes` maps changed fields to JSON `{from,to}` pairs. Represent missing prior values with `null`. Use target types `streamSettings`, `video`, `scheduleEntry`, `scheduleException`, `scheduleSettings`. |

## Persistence and relationships

- All new mutations use `new Date().toISOString()` for audit time. Use one date and actor across the domain and audit changes of a single user action. Use collision-resistant string ids for new entities and actions. Preserve original `createdAt` when editing. Keep the object and its event in the same saved snapshot. The active actor originates from `account.id`; seeded actor ids can refer to `moderators`.
- Stream, video and schedule category ids join `categories`. If the injected taxonomy omits a referenced id, show a readable category fallback and preserve the id unless the editor replaces it. Apply the same fallback principle to missing actors and related viewers. Default missing optional collections for rendering and preserve injected data untouched on boot after template initialization.
- For publication, set `publishedAt` on publish and clear it on unpublish. Deletion retains the row and records deletion time for inspection, preserving the preceding publication timestamp. Bulk operations append an event per affected entity. Missing optional fields and unknown injected properties survive unrelated edits.
- An unban or timeout removal clears `restriction` while preserving the original log. Expiration is a derived display state and produces no write. A moderation event is the audit record for a moderation action. Use `stateChanges` only for settings, videos and scheduling.
- Show recurrence from the anchor using local wall time in the stored timezone. Key a weekly occurrence by entry id and local date and apply exceptions only to matching projected dates. Restore updates the existing exception; removing a series hides its future projections while preserving exceptions for inspection. A change to vacation settings records the enabled flag and date range, with dates nullable when disabled. Derived agenda and vacation markers stay outside state.
- Edits append action names from [TODO.md](../TODO.md). A changed mutation produces exactly one store save. A duplicate change, abandoned form, or invalid input produces none. `/go` exposes changed keys in `state_diff`, and current records in `current_state`.

## Deterministic fixtures

`createInitialData()` returns the complete root shape with fresh objects/arrays and deterministic ids, dates and counts. Use fixed timestamps for existing recordings and action history. Anchor the agenda with fixed relative-day offsets from the runtime date in the channel timezone so the initial view has upcoming one-time programs under Harbor’s frozen clock. Give each slot a fixed id by fixture index, and keep server and client calendar calculations aligned through the explicit timezone.

| Entity | Count and useful variety |
| --- | --- |
| Account and moderators | Rhea Mercer (`creator-001`) and two named moderators. |
| Categories | 24 English names including Art, Makers & Crafting, Photography, Music, Talk Shows & Podcasts, and Just Chatting. Use consistent ids and local cover styles. |
| Videos | 36, including 24 past broadcasts, 8 highlights and 4 uploads. Use at least 8 unpublished entries across types, with varied descriptions, views, durations and dates. Sample titles include “Bookbinding after hours”, “Contact sheets from the coast”, and “Mixing an iron glaze”. |
| Viewers and chat | 32 viewers with varied logins, at least two active bans, two active timeouts and two elapsed timeouts. Use 48 English chat messages distributed across profiles, with multiple visible messages for representative targets and at least one seeded deletion. Whole minutes and seconds are integers. |
| Moderation log | 30 fixed-id records spanning all planned action types and both moderators. Keep referenced viewer, message, and action ids coherent, including the effective latest restriction. Anchor active/elapsed timeout fixtures relative to the runtime clock at seed time. |
| Schedule | 30 slot records distributed across past and coming weeks, including six weekly series and one-time streams in the first displayed week. Include cancelled entries, and at least two weekly exceptions that match projected dates. Example series “Friday print lab”, single event “Museum sketchbook swap”. |
| State changes | Empty to start. Recorded fixtures in `modActions` give the workspace historical context. |
