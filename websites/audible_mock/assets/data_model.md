# Audible Account Data Model

`createInitialData()` returns one JSON object with the nine keys below. Timestamps are ISO 8601 UTC strings and optional relationships may be omitted. The store preserves additional injected keys and fields. Balance, expiration, and eligibility indicators are derived from the relevant records.

## Relationships and transitions

- The member owns all account records through `actorId`. Resolve catalog metadata by `titleId`. Resolve the purchased library entry by `purchaseId`. Exclude removed and returned library entries from the active view. Preserve prior records when a title is reacquired, and guard against duplicate active ownership.
- `libraryActivity[]` records the resulting values each time a library action changes an entry. Set `quantity: 1` in each activity row. Capture one `new Date().toISOString()` per transaction for all fields written together. Use unique runtime IDs for new records and fixed IDs for fixtures.
- `Add to Library` creates an active included entitlement with `not_started` and `0` progress. If the same included record was removed, reactivate it and keep prior listening progress. Removal applies to included entitlements and preserves the row. Finish and unfinish only apply to active entries.
- Derive the balance from `available` credits that have been issued and have no expiration date or expire after `now`. At redemption confirmation, check active Premium membership, `creditEligible`, the balance, and lack of active ownership. Choose the earliest-expiring available credit, then oldest issue date, then ID. Credits without `expiresAt` sort after dated credits. Mark the chosen row `spent` and set `purchaseId` and `spentAt`. Append the `redeemed` transaction and a completed order. Create an active purchased entitlement with zero progress and append `acquired` activity. If the title has an active Wish List row, set it to `purchased`, link the order, and stamp `updatedAt`. Commit together in one user-action save.
- A return requires an active Premium member with `canReturn` enabled, a completed credit order with a valid purchase timestamp no more than 365 elapsed days old and not in the future, and no matching return or per-order block. At confirm, stamp `returnedAt` and `returnId` on the order and mark it `returned`. Set a matching active purchased entitlement to `returned`, stamp `updatedAt`, and append `returned` activity with the order and refund links. Append the refund record and issue a new `available` credit with `source: 'return'` and `returnId`; give it a timestamp 12 calendar months after issuance in UTC, clamped to the last day when needed. Append the `refund` ledger row using the new credit, title, order, and return IDs. Retain the original spent lot. A missing entitlement does not invalidate an otherwise eligible order.
- Saving creates an independent `saved` Wish List row. Removing changes the active row to `removed` and stamps `updatedAt`. Re-saving creates a new row and preserves history. Included additions and returns have no direct Wish List effect.
- Treat optional display metadata as absent when missing. For missing linked titles, show stable fallback labels and keep otherwise valid purchase/refund records viewable. Missing eligibility or unusable data disables the action that depends on it. Accept empty arrays and avoid mutating the injected object during normalization.

## Suggested defaults

- `account` uses the synthetic member from the table. `titles` contains 72 fictional English audiobooks with fixed IDs `title-001` through `title-072`, varied genres, author/narrator names, cover palettes, and runtimes. Include owned titles, unowned titles with credit actions, unowned included titles, and unavailable titles.
- `purchases` contains 26 orders, including two historical returned orders. `library` holds 26 corresponding purchase entitlements, including their returned rows, plus six included entries. Use progress values of 0, 100, and several intermediate positions. Include at least one removed included entry.
- `wishlist` contains 26 entries, spanning active, removed, and purchased statuses. Include an active credit-eligible unowned title and an active included unowned title. Avoid multiple active rows for a title.
- Use 2026-11-18T12:00:00.000Z as the fixture reference. Include three credits valid then, one expired unused lot, one historical spent lot per credit-funded order, and linked credits for the two historic returns. Seed at least one recent self-service credit order, one blocked credit order, one older than 365 days, and several cash orders. Use matching ledger records for all seeded credit and library changes. All fixture IDs and timestamps are deterministic. Tests for time-sensitive behavior should inject their own dates against a fixed browser clock.
