## P1 — Primary workflows

All writes below include the record metadata shown in the [state model](assets/data_model.md). An insert sets `createdAt/createdBy` and `updatedAt/updatedBy`. An edit updates `updatedAt/updatedBy`. Each committed command appends one typed `activityEvents[]` record for the subject and links the other affected IDs. Cancel, validation failure, and read-only interactions leave the business snapshot untouched.

- [x] **P1.1 · Review invoices and payment history.** Show All Invoices with checkboxes, search, Advanced Search, sortable issue/due dates and amount, client and status filters, and an active/archived/deleted view switcher. Show invoice number, client, description, issue/due date, amount, balance and status per row. The detail page shows line items, amount due, payment history, and Edit/More Actions. Clients show linked invoices and retainers with preselected New actions. The Payments list links each row to its invoice. No business writes for these views.
- [x] **P1.2 · Create, edit and duplicate invoices.** Provide searchable Bill To, invoice number, issue/due dates, reference, currency, and Add a Line with catalog and custom entries. Each line supports description, rate, quantity, tax, reordering and removal. Show live subtotal, discount, tax, total and amount due, plus notes and terms. Validate unique invoice number, client, dates, and positive quantities on Save. Save inserts or edits `invoices[]` (`clientId/projectId`, `invoiceNumber`, `issueDate/dueDate`, `currency`, `reference`, `lines[]`, `discountPercent`, `notes/terms`, `subtotal/discountAmount/taxAmount/total/amountPaid/amountDue`, `status/visibility`). New invoices begin as `draft`. Duplicate opens an editable draft and inserts a new invoice only on Save, with a new ID/number and copied commercial fields.
- [x] **P1.3 · Send, mark sent, record payment and manage visibility.** Send To opens a recipient/message/attach-PDF dialog and commits on Send Invoice. Mark as Sent is a separate confirmation for drafts. Both write `invoices[].status/sentAt` as applicable. Send adds `activityEvents[].delivery` with recipient addresses, message and PDF preference. Add a Payment records `payments[]` with `invoiceId/clientId`, `paymentDate`, `currency/amount`, `method`, `reference/notes` and `status`, then writes `invoices[].amountPaid/amountDue/status` for partial or full payment. Refuse zero, negative and over-balance amounts. Archive, Delete and Restore write `invoices[].visibility`. Delete releases linked ordinary time/expense sources, setting their `invoiceId` to null and `status` to `unbilled`. Restore checks those links for conflicts before relinking. Retainer invoice deletion rules are in the state model.
- [x] **P1.4 · Log and manage time.** Time Tracking opens Day with date navigation, hours logged by, daily total, New Entry, Start Timer and Generate Invoice. All shows searchable/sortable rows with team member, date, client/project/service, notes, duration and billing status. Provide client, member, date range and billing status filters and bulk Mark as Billed/Unbilled and Delete for eligible rows. A manual entry supports decimal hours, `1h 30m` and `1:30`, notes, Billable and conditional Apply to Retainer. Save inserts or edits `timeEntries[]` (`userId`, `workDate`, `durationMinutes`, `clientId/projectId/serviceId`, `notes`, `billable/status`, `invoiceId`, `retainerId/retainerPeriodStart`, `visibility`). Manual billing changes `status` and Delete changes `visibility`; guard time already attached to a live invoice and recalculate any affected retainer display.
- [x] **P1.5 · Start, pause, resume, discard and log a timer.** A compact timer stays usable across routes. It accepts the same assignment and notes as manual time and lets the user adjust the duration before Log Time. Start writes `activeTimer` with an ID, actor, running status, start timestamp and zero accumulated seconds. Pause writes `status/startedAt/accumulatedSeconds`. Resume writes `status/startedAt`. Discard clears `activeTimer`. Log Time clears it and inserts the finalized `timeEntries[]` row with `timerId`, normalized duration and billing links in one commit. The on-screen elapsed clock uses the stored times and `new Date()`. Rounding and the zero-duration case are defined in the state model.
- [x] **P1.6 · Review and record expenses.** Show All Expenses with selection checkboxes, merchant/category, date/source, client/project/description, and amount/tax/status. Provide search, date/category/client/billing filters, sortable date/amount and a New Expense row for quick entry. The full editor includes category, date, merchant, description, editable gross total, tax amounts, currency, and Assign to Client/Project. Default to Uncategorized Expenses. Save inserts or edits `expenses[]` (`merchant/categoryId`, `expenseDate`, `description/source`, `currency/total/taxes`, `clientId/projectId`, `billable/status`, `markupPercent/includeReceiptOnInvoice`, `invoiceId`, `receipt`, `visibility`). Duplicate opens an editable copy with billing links and receipt cleared. Archive/Delete/Restore change `visibility` with the linked-invoice guards in the state model. Bulk category change edits each selected `categoryId`.
- [x] **P1.7 · Attach receipts and assign expenses for rebilling.** Attach a JPEG, PNG or PDF by selecting a file or dropping it in the editor. Keep the file selection provisional until Save, use same-origin `POST /upload?sid=…` for the selected file, and render the saved preview/download via its local URL. Save/removal writes `expenses[].receipt` as metadata or null. In Assign to Client/Project, select a client or one of its projects, toggle Mark as billable, specify a markup percent and optionally Include receipt image on invoice. Save writes `clientId/projectId/billable/status/markupPercent/includeReceiptOnInvoice`; a valid billable expense starts as `unbilled`.
- [x] **P1.8 · Invoice unbilled time and expenses.** Start from Generate Invoice in Time Tracking, or Add a Line → Import Unbilled Time and Expenses in an invoice. Review the selected client, date range and projects (including No Project), expense inclusion, and Detailed, Grouped or Simple time format. Preview lines with traceable source IDs and allow cancellation. On invoice Save/Send, insert or edit `invoices[]` and `invoices[].lines[].sources[]`, writing each included `timeEntries[]` and `expenses[]` row's `invoiceId/status=billed` in the same commit. Release removed sources on save (`invoiceId=null/status=unbilled`). Check same-client, same-currency and source availability immediately before commit. Use the allocation and rounding rules in the state model.
- [x] **P1.9 · Create and edit retainer terms.** The Retainers list supports client search, status and visibility filters and shows client, cadence, fee, hours, next issue date and state. New Retainer opens the Set Up Your Retainer form for client, start, Weekly/Monthly/Yearly/Custom period, fee, included hours, excess rate, next issue date, invoice count (Infinite or a specific number), and invoice delivery mode. Set and Continue opens the invoice-style preview. Final Save inserts or edits `retainers[]` with `clientId`, `startDate`, `periodUnit/customPeriodDays`, `feePerPeriod`, `includedMinutes`, `excessHourlyRate`, `currency`, `nextIssueDate/scheduleAnchorDate/scheduleIndex/periodIndex`, `invoicesRemaining/deliveryMode`, `invoiceNotes/invoiceTerms`, and `status/visibility`, and creates or updates the applicable `retainerPeriods[]` snapshot (start/end, included minutes, fee, rate/currency). Enforce one active retainer per client, including archived active retainers. Edit Terms uses the same form and preserves issued-period financial terms.
- [x] **P1.10 · Track time against a retainer.** The detail view shows selected period, Hours Logged, remaining budget, excess and next billing date, with Invoices, Time Entries and Projects tabs. Apply to Retainer is available in time forms for a matching eligible client/date and selected by default where eligible. A qualifying time save writes `timeEntries[].retainerId/retainerPeriodStart`, `billable=true`, `status=billed` and `invoiceId=null`, and opens the `retainerPeriods[]` snapshot if needed. Unchecking it on a later editable time entry clears the retainer link and recomputes `status`. A project edit can set or clear `projects[].retainerId` for future entries. Recalculate totals from the linked records, including after edits and deletes.

It writes `retainerPeriods[].feeInvoiceId` and `retainers[].scheduleIndex/periodIndex/nextIssueDate/invoicesRemaining/status`, advancing exactly once. Show the linked invoice in both lists. View and clock changes only recalculate eligibility.
- [x] **P1.12 · Bill excess hours and manage retainers.** For a closed period with eligible excess and a positive rate, show Generate an Invoice with the remaining hours and fee. The editor previews a linked draft and on Save/Send inserts `invoices[]` with `kind=retainer_excess`, `retainerId/retainerPeriodStart` and the per-entry `lines[].sources[].minutes/amount` allocations. Period totals and excess already billed derive from those links. Archive/Delete/Restore write `retainers[].visibility`, guard conflicts on restore, and retain historical time and invoices. A deleted retainer stops generating fees and accepting new time.
