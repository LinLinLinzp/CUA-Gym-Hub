## P1 — Properties, URL inspection and sitemaps

- [x] **Properties list and switching.** Show searchable and filterable active and pending properties with label, type and verification state. Provide the same search and selection from the workspace control. Selecting another property updates the shell and scopes all data to it, clearing any inspection or detail context that belonged to the previous property. Persist `account.activePropertyId` and append `propertyEvents[]` with `type: selected`. Keep queries and filters in view state. Mark the current property and handle empty results and missing optional fields.
- [x] **Add and verify a property.** Offer Domain and URL prefix choices and matching example inputs. Normalize and validate inputs before local verification. Domain uses DNS record verification, while URL prefix offers HTML file or HTML tag. Show synthetic method instructions, Verify and Verify later. Cancel leaves state untouched. Verify creates a verified owner, selects it and records both add and verification events. Verify later creates a pending row with a matching Add event. Reopen pending rows to finish verification. Display duplicate errors and allow re-adding a previously removed scope. Writes go to `properties[]` (`status`, `permissionLevel`, verification fields and timestamps), `account.activePropertyId` when activated and `propertyEvents[]` (`added`, `verified` or `restored`).
- [x] **Property details and removal.** Show scope, verification, permission and date added. Confirm Remove property by naming the property. Mark `properties[].status` as `removed` and write `removedAt` and `removedBy`. Append a `propertyEvents[]` record of type `removed`. If the active property was removed, update `account.activePropertyId` to the first remaining verified property in stable state order or `null`. Keep existing linked records available to the verifier. Cancel writes nothing.
- [x] **Inspect a URL.** Submit a full HTTP(S) URL from the global form or URL Inspection page. Validate membership against the selected property's domain or exact origin and prefix. Show a scoped error for an invalid or out-of-property URL. For a valid URL, present the Google Index verdict with details for discovery, crawl, canonical and indexing status. Show a URL-unknown result for an unseeded page. Append `inspections[]` with property ID, normalized URL, index snapshot and actor/time. Opening recent history, following a result deep link or switching result tabs reads existing data without appending a record.
- [x] **Test live and request indexing.** Show **Test live URL** and **Request indexing** on the result. A live test appends `liveTests[]` with inspection ID, property ID, URL and a synthetic result, then opens the Live Test tab. A rerun adds another linked record. Report fetch and indexing controls independently of Google Index. A request appends `indexingRequests[]` with `status: queued`, property/inspection IDs, URL, optional live-test ID and actor/time. Show confirmation and surface the existing request on repeat clicks for the same property and URL. If the latest test fails, or the same local eligibility check fails before a live test, explain the block without queueing a request. A queued request does not change the Google Index verdict.
- [x] **Sitemap report, submission and retry.** Show **Add a new sitemap** and a searchable, status-filterable, sortable submitted-sitemaps table. Columns cover sitemap URL, type, submitted date, last read, status, discovered pages and discovered videos. Paginate at 10 rows and default to newest submitted first. Accept a same-property absolute URL or relative path when the UI shows its full base. Validate the scope and reject fragments. Create or reactivate the row, or update the existing row for the same property and canonical URL when resubmitting. Write `sitemaps[]` fields for URL, submission status, submitted time, actor and count, and append `sitemapEvents[]` with `submitted` or `resubmitted`. New and retried submissions enter `pending` synchronously. Offer a resubmit action for failed or changed maps and confirm that Search Console received the submission.
- [x] **Sitemap details and removal.** Link each row to a reload-safe details page showing URL, status, submitted and last-read date, discovered counts and any issue details. Provide **Resubmit sitemap** and a menu action for **Remove sitemap**. Confirm the URL before removing. Set `sitemaps[].status`, `removedAt` and `removedBy`, append `sitemapEvents[]` of type `removed`, and return to the property-scoped list. Verify that re-submission restores the same record, the cancelled confirmation writes nothing, and removal leaves related inspection history intact.
