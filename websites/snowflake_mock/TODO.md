## P1 · Warehouses

- [x] **Find and inspect.** Search names or comments, filter by status and size, and sort by name or last updated. Show name, status, size, clusters, running, queued, and owner. The detail page shows compute settings, current workload counters, and recent actions from `activity`. Opening, searching, filtering, and sorting write nothing.
- [x] **Create and configure.** Offer Name, Size, Auto suspend (seconds, with 0 meaning disabled), Auto resume, Start suspended, Min clusters, Max clusters, and Comment. Default to X-Small, 300 seconds, auto resume enabled, start suspended, and one cluster. Canonicalize unquoted identifiers to uppercase and reject duplicate names, negative or non-integer auto-suspend values, and cluster ranges outside `1 ≤ min ≤ max ≤ 10`. Edit size, timeout, auto resume, clusters, and comment using prefilled values. Create appends a `warehouses` record with `status`, settings, owner and timestamps and a `warehouse.created` event. Save updates the changed settings and `updatedAt`, then appends `warehouse.updated` with the changed fields.
- [x] **Operate and remove.** Show Resume only for Suspended and Suspend only for Started. Confirm each and set `warehouses[].status`, `updatedAt`, `activeClusters` (`minClusters` on resume, `0` on suspend), and `running` and `queued` (both zero), with a `warehouse.resumed` or `warehouse.suspended` event. Drop a warehouse after confirmation, clear its ID from any worksheet context, revoke its active warehouse privilege grants, and retain historical query snapshots. Save those changes and the `warehouse.dropped` event in one transaction.

## P1 · Worksheets

- [x] **Find, create, and manage.** Search by title or SQL and sort by most recently updated or name. A new worksheet has an editable title and blank SQL. Creation writes `worksheets` and `worksheet.created`. Renaming, saving SQL, and applying Role, Warehouse, Database, and Schema context update `worksheets[].title`, `sql`, or `context`, and `updatedAt`, with `worksheet.updated`. Use visible Save and support Ctrl+S in the editor. The editor indicates pending edits and prompts on in-app navigation if needed. Confirm deletion, remove the worksheet, retain its query records, and append `worksheet.deleted`.
- [x] **Run SQL locally.** Provide a Run button and Ctrl+Enter. Execute a selected statement or the statement at the cursor, defaulting to the first statement if the cursor is between statements. Support literal `SELECT` with optional aliases, `SELECT CURRENT_ROLE(), CURRENT_WAREHOUSE()`, `SHOW WAREHOUSES`, `SHOW ROLES`, and `SELECT * FROM [database.schema.]ORDERS [LIMIT n]` over seeded sample rows. Derive SHOW rows from the loaded state. Show a visible, actionable error for invalid or unsupported input. A nonempty Run saves pending worksheet edits and appends a `queryRuns` record with SQL, worksheet and context snapshots, status, row count, duration, columns/rows or an error, and actor and time. Append `worksheet.query_ran` with the run ID. For supported SELECT, require a valid selected warehouse and resume it in the same transaction when suspended with auto resume enabled. Surface a clear error when auto resume is disabled. SHOW commands can run without warehouse compute. A blank Run only shows validation feedback. Empty, success, and error panels and a worksheet’s recent runs must all render cleanly on reload.

## P1 · Roles

- [x] **Find and inspect.** Search by role name or comment; filter System or Custom and sort by name. Detail shows owner, comment, direct user assignments, roles granted to this role, parent roles, and warehouse privileges. Label grant direction with concrete names (for example, `BI_READER` granted to `SYSADMIN`) and derive counts and hierarchy from active `grants` records. Reading these views writes nothing.
- [x] **Create and maintain.** Create a custom role with an uppercase unquoted identifier, optional comment, and optional parent role. Reject duplicate names. Creation writes `roles`, `role.created`, and, when a parent is chosen, an active `grants` record linking the new child to that parent and a `grant.created` event in the same transaction. Edit a custom role’s comment and write `roles[].comment`, `updatedAt`, and `role.updated`. Confirm deletion of a custom role, remove the role, revoke active related grants, and clear current references from worksheets and owned objects as detailed in the [data model](assets/data_model.md). Add a `role.dropped` event. Keep system roles protected and historical runs and events readable.
- [x] **Grant and revoke.** Grant the selected role to a user or to a parent role. Also grant `USAGE`, `OPERATE`, or `MONITOR` on a warehouse to the selected role. Require a valid target, reject duplicate active grants and role cycles, and show grant direction in the confirmation. Grant appends an active `grants` record with `grantedByUserId`, `grantedByRoleId`, and `createdAt`, plus `grant.created`. Revoke updates `status`, `revokedAt`, and `revokedByUserId` and appends `grant.revoked`. Keep revoked records for verification. Regranting creates a new grant ID.
