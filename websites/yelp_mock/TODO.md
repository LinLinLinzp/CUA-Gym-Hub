## P1 — Primary Features

- [x] **Discovery and entry points.** Search by business name, category, or description and optionally by city or neighborhood. Provide category and bookable/quote-capable filters and a reset action. Results show name, category, neighborhood, rating when known, and capability labels. Listings open business detail, which shows location, published reviews, and Save, Write a review, Request a quote, and Find a table according to record eligibility. Search and filter changes write no domain state.
- [x] **Reviews.** From business detail or the Reviews page, choose a business, select an integer rating from 1 to 5, enter at least 85 trimmed characters, and post. Confirm success and show the published record in My reviews and on the business. My reviews lists the signed-in user's published reviews with business, rating, date, text, and labeled edit/remove controls. Allow editing rating and text, and confirm removal with a reason. A second Write a review for the same business opens the existing published review for editing. Create writes `reviews[]` with `id, userId, businessId, rating, text, status: 'published', createdAt`. Edit writes `rating, text, updatedAt` to that ID. Removal writes `status: 'removed', removalReason, removedAt, updatedAt` to that ID and hides it from published views.
- [x] **Bookmarks and collections.** Save from a business page, choose an owned collection, and see its saved state immediately. Default to “Want to go” where present. The account page shows collection counts and offers search within a collection. Allow creating a named collection from the account page or Save dialog and removing a saved business from its collection with confirmation. Create a collection in `collections[]` with `id, userId, name, status: 'active', createdAt`. Saving writes `bookmarks[]` with `id, userId, businessId, collectionId, status: 'saved', createdAt`; enforce one active membership per user/business/collection. If an injected world lacks collections, offer Create collection and make an explicit save to the default collection create both records in one mutation. Removal writes `status: 'removed', removedAt, updatedAt` to the selected bookmark. Re-saving appends a new saved record and retains the removed record.
- [x] **Quote requests.** From an eligible service business or the account page's Find a service action, collect service type, project details, service ZIP, and preferred date if supplied. Validate the service against offered options, require a description and five-digit ZIP, and reject an entered date in the past. Review the request before submitting. Open its detail, show it under Active in the account, and allow confirmed archiving. Active and Archived tabs show the business, subject/service, submission date, and status. Submit adds `quoteRequests[]` with `id, userId, businessId, serviceType, details, zipCode, preferredDate` (null if blank), `status: 'submitted', createdAt`. Archive writes `status: 'archived', archivedAt, updatedAt` to that record. Any seeded quote amount is displayed from the record. The app generates no replies or quotes.
- [x] **Reservations.** From a bookable business or the Reservations page's Find a table action, choose date, approximate time, and party size, then pick a returned slot and confirm guest name and email with optional phone and notes. Show the confirmation code and detail link. Account view shows Upcoming and History, with a confirmed past slot displayed in History based on the task clock. Allow modifying a future confirmed booking by choosing a new available slot, and allow confirmed cancellation. Confirm adds `reservations[]` with `id, userId, businessId, date, time, partySize, guestName, email, phone, notes, confirmationCode, status: 'confirmed', createdAt`. Modify writes `date, time, partySize, updatedAt` to the same ID. Cancel writes `status: 'cancelled', cancelledAt, updatedAt`. Slot searches, draft changes and invalid submissions write no records. Use the slot and timezone rules in the data model.
- [x] **Local workflow verification.** On Windows run `npm run build` and test only on `http://localhost:5319` with Chromium and the installed Playwright resolved from `PILOT_PLAYWRIGHT`. For a persistent server use PowerShell `Start-Process -WindowStyle Hidden` with an absolute `node_modules/vite/bin/vite.js` entry point and the site as its working directory. Put scratch runners in a gitignored location or remove them when done. Use a unique test `sid` per scenario. In the review scenario, post → edit → remove; for bookmarks, create a collection → save → remove; for quotes, submit → archive; for reservations, book → modify → cancel. At each step assert the visible outcome, poll `/go?sid=…` for the listed fields, and verify the same records after reload. Cover invalid input, duplicate clicks, empty/sparse injected data, session isolation, and navigation/reload without idle state writes after the initial baseline. The Playwright phase records evidence and exact changed fields in `TEST.md`. The parent runner handles Docker dynamic certification and commits.
