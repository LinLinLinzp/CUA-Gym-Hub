# Proposed Harbor state model

Use JSON objects and arrays. IDs are strings and fixed in the seed. Generate IDs for new business records once per accepted action. Use ISO 8601 UTC strings for timestamps and `null` for absent optional values in the seed. Generate action timestamps with `new Date().toISOString()`. The examples show a synthetic course at different stages of its lifecycle.

## Store shape and examples

| Top-level key | Type | Record fields and example values |
| --- | --- | --- |
| `learner` | Object | `id` string, `displayName` string. Example `{ "id": "learner-001", "displayName": "Maya Chen" }`. |
| `courses` | Course[] | `id`, `title`, `issuerName`, `topic`, `level`, `description`, `artworkKey` strings. `estimatedMinutes` number and `certificateEligible` boolean. `modules` array of objects with string `id` and `title`, ordered string arrays `lessonIds` and `assignmentIds`. Example course `course-archive`, **Inside the Community Archive**, Alder Institute for Public History, Museum Studies, Beginner, `120` minutes, eligible, artwork `archive`, module `module-archive-01` titled **Reading the collection** linked to `lesson-archive-01` and `assignment-archive-01`. |
| `lessons` | Lesson[] | `id`, `courseId`, `title` strings, `estimatedMinutes` number and `paragraphs` string[]. Example `lesson-archive-01`, `course-archive`, **Read an object label**, `12`, original paragraphs about describing donated objects. |
| `assignments` | Assignment[] | `id`, `courseId`, `title`, `instructions`, `type` strings (`type: "quiz"`), `estimatedMinutes`, `passingPercent` numbers, optional `dueAt` ISO string or null, and `questions` array. Example `assignment-archive-01`, `course-archive`, **Cataloging basics**, **Select one answer per question**, `8` minutes, `75` passing, `2026-11-24T17:00:00.000Z`. Each question has string `id`, `prompt` and `correctOptionId`, plus `options` array of objects with string `id` and `label`. Example `q-archive-01`, **Where should the source of an object be recorded?**, options `opt-provenance` (Provenance field) and `opt-display` (Display location), correct `opt-provenance`. |
| `enrollments` | Enrollment[] | `id`, `learnerId`, `courseId`, `status`, `createdAt`, `updatedAt` strings, `progressPercent` number, and optional ISO strings or null for `completedAt`, `withdrawnAt`, `reenrolledAt`. Example `enrollment-010`, `learner-001`, `course-archive`, `in_progress`, `50`, created `2026-11-03T12:00:00.000Z` and updated `2026-11-08T15:00:00.000Z`. Status values `in_progress`, `completed`, `withdrawn`. |
| `lessonCompletions` | LessonCompletion[] | `id`, `learnerId`, `enrollmentId`, `courseId`, `lessonId`, `status`, `createdAt` strings. Example `completion-022`, `learner-001`, `enrollment-010`, `course-archive`, `lesson-archive-01`, `completed`, `2026-11-08T15:00:00.000Z`. Unique per enrollment and lesson. |
| `assignmentAttempts` | AssignmentAttempt[] | `id`, `learnerId`, `enrollmentId`, `courseId`, `assignmentId`, `status`, `createdAt` strings. `attemptNumber` and `scorePercent` numbers. `answers` array of objects with string `questionId` and `optionId`. Example `attempt-075`, `learner-001`, `enrollment-010`, `course-archive`, `assignment-archive-01`, `failed`, `2026-11-09T15:00:00.000Z`, attempt `1` with score `0` and answer `{ "questionId": "q-archive-01", "optionId": "opt-display" }`. Status values `passed`, `failed`. |
| `certificates` | Certificate[] | `id`, `learnerId`, `enrollmentId`, `courseId`, `courseTitle`, `learnerName`, `issuerName`, `verificationCode`, `status`, `createdAt` strings. Example `certificate-024`, `learner-001`, `enrollment-010`, `course-archive`, **Inside the Community Archive**, **Maya Chen**, **Alder Institute for Public History**, `ARC-24F6C7`, `issued`, `2026-11-11T16:30:00.000Z`. Store names as issuance snapshots. Issue at most one credential per learner and course. |
| `certificateActions` | CertificateAction[] | `id`, `learnerId`, `certificateId`, `courseId`, `type`, `status`, `createdAt` strings. `type` is `download` or `copy_link`, `status` is `completed`. Include `fileName` string only for downloads or `verificationPath` string only for copied links. Example `action-030`, `learner-001`, `certificate-024`, `course-archive`, `download`, `completed`, `2026-11-11T16:40:00.000Z`, `inside-the-community-archive-certificate.pdf`. |

`createInitialData()` returns a fresh object with the nine keys listed above. Define modules inside the course, and use IDs to join learner activity to a course and enrollment. Enrollments are unique per learner and course. Each attempt, completion and certificate references the same learner and course IDs as its enrollment. Certificate actions reference the certificate, and verification code lookup uses certificate snapshots so a detail page survives catalog edits or sparse injections. The seed may leave `certificateActions` empty.

## Course rules

- Resolve requirements from module lesson and assignment IDs, deduplicated by kind and ID. An empty course or an outline with unresolved requirement IDs cannot be finished. Show an explanation for missing course content. Missing optional display fields can use safe fallbacks.
- Derive active progress as `Math.round(100 * fulfilled / total)` for courses with requirements and use `0` for an empty active outline. A completed lesson counts once and a quiz counts once if at least one owned attempt passed. Evaluate readiness from the requirements, independent of display rounding. An injected historical completed record can render as completed without rebuilding or backfilling it.
- Require one valid option per question, distinct valid question IDs and a usable answer key for quiz submission. Compare the exact correct-answer ratio against the threshold and store the score rounded to two decimals. Assign the next attempt number from the largest previous attempt number for that enrollment and assignment plus one. Allow retakes for failed work on an active enrollment.
- Read, mutate and publish the latest state snapshot in one store action. Recheck eligibility and IDs in the same operation. For an accepted lesson or quiz action, save the updated record array and enrollment together. For **Finish course**, save the completed enrollment and any issued certificate together. Preserve all unrelated fields. Keep dates, sorting, derived statuses and fallback displays free of automatic writes.
- Download means the browser download was initiated, and copy means the clipboard write succeeded. Keep certificate `verificationPath` as a relative path such as `/verify/ARC-24F6C7?sid=training-01`. Open or copy its same-origin absolute URL using the current origin.

Create the implementation's `SCHEMA.md` from this model and the final store. Match the Harbor template format for `/go`: a changed top-level key appears in `state_diff` with the replacement value under `modified` or `added`. Use `current_state` for exact row assertions.
