## P1 — Primary workflows

- [x] **Claims — Find and track a claim.** Search by ID, type, or condition and filter active versus decided claims. Show filed date, status and last update on list rows. Detail shows conditions, status history, evidence requests and submitted files, with a local decision-letter download when available. Browsing and downloading have no state writes.
- [x] **Claims — File for disability compensation.** From Claims, open a short application with claim reason (new condition or increase), one or more condition names, review, and an acknowledgment checkbox. Reject blank conditions and submit only from review. Show confirmation and link to the new claim. Append `claims[]` with `status: received`, `type: disability_compensation`, `reason`, `conditions`, `acknowledged: true`, `createdAt`, `updatedAt`, `actorId`, and an initial `history[]` entry. Use the [claim shape](assets/data_model.md#claims).
- [x] **Claims — Add evidence.** On a pending disability claim, choose a document type and select a local PDF, GIF, JPEG, BMP or TXT up to 25 MB. Show the filename and allow replacement before submitting. Save file metadata and confirmation in the claim's evidence list. Append `claimEvidence[]` with `claimId`, `fileName`, `mimeType`, `sizeBytes`, `documentType`, `status: submitted`, `actorId`, and `createdAt`. Update `claims[].updatedAt` on the linked claim. Represent the selected file by its metadata in this exercise.
- [x] **Appointments — Browse and request a visit.** Show Upcoming (scheduled future visits), Requests (pending requests), and Past (completed, canceled, and elapsed scheduled visits), with search by clinic, facility, or visit type. Detail shows time or preferred time, facility, visit format, and status. Request flow collects facility, clinic, visit format, future preferred date/time, and reason. Confirm a request with a reference ID and list it under Requests. Append `appointments[]` with `status: requested`, `facilityId`, `clinic`, `visitType`, `preferredDate`, `preferredTime`, `reason`, `actorId`, `createdAt`, and `updatedAt`. Browsing has no state writes.
- [x] **Appointments — Cancel a request or eligible visit.** Open confirmation for pending requests or future scheduled visits with `canCancel: true`. Allow an optional reason and provide a way to dismiss. On confirmation update the same `appointments[]` row with `status: canceled`, `canceledAt`, `canceledBy`, `cancelReason`, and `updatedAt`. Keep the original details and move it to Past.
- [x] **Prescriptions — Find medication, request a refill, and track delivery.** Search medication or Rx number and filter by display status. Detail shows remaining refills, fill history and saved shipment tracking when present. Allow one refill at a time for an active prescription with positive `refillsRemaining` and no pending refill. Review and confirm a single refill, show its request ID, and indicate Refill requested on the row. Append `refillRequests[]` with `prescriptionId`, `quantity: 1`, `status: requested`, `actorId`, and `createdAt`. Derive the display status from the pending request and leave the remaining supply count as recorded. Browsing and viewing shipment details have no state writes.
- [x] **Payments — Review benefits and change direct deposit.** Show incoming payment history with benefit type and year filters. Each payment detail shows date, amount, type, status and method. A Direct deposit action opens a separate view where the user selects a benefit group and a different labeled synthetic destination, reviews its masked details, and confirms the change. Upsert `directDeposits[]` for the benefit group with `destinationId`, `status: active`, `actorId`, `updatedAt` and stable record identity. Append `directDepositChanges[]` with `directDepositId`, `benefitGroup`, `previousDestinationId`, `destinationId`, `status: saved`, `actorId`, and `createdAt`. Viewing or filtering history has no state writes. Historical payments retain their original destination display.
- [x] **Payments — Pay a copay bill.** Show copay bills separately from incoming benefits, with open/paid filtering and details for facility, line items, due date and balance. On an open bill, review and confirm the full balance using a labeled synthetic payment method. Show a receipt with amount and ID. Append `copayPayments[]` with `billId`, `amount`, `currency`, `method`, `status: paid`, `actorId`, and `createdAt`. Set `copayBills[].status: paid`, `balance: 0`, `paidAt`, and `updatedAt` together with the receipt append. Paid bills retain the original line items and link to the receipt through the bill detail.
