## P1 — Required workflows

- [x] **Folders — browse, search, and create.** Show mixed folders and files, breadcrumbs, name and modified sort, and type filtering. Clicking a folder opens its contents. Clicking a file opens a local document preview with an Activity pane. Search matches names case-insensitively and shows ancestor paths. From All files or an open folder, **New folder** opens a form with a required name and optional description and invitees. Trim the name, reject path separators and duplicate active sibling names, and allow the same name elsewhere. The active route supplies the parent. **Writes:** append one `folders` record with `id`, `parentId`, `name`, `description`, `ownerId`, `status`, `createdById`, `createdAt`, `updatedById`, and `updatedAt`. Prevalidate optional invitees and commit their `collaborations` records in the same transaction.
- [x] **Folders — rename, move, trash, and restore.** Put these actions in the folder row menu and detail header where applicable. Rename preloads the current name. Move opens a folder picker with breadcrumbs and rejects the current parent, the source itself, its descendants, trashed folders, and duplicate destination names. Trash confirms the target name and hides the entire subtree from active views without breaking descendant links. Trash lists directly trashed folders. Restore under the original active parent, or ask for an active destination if the original is unavailable or conflicting. **Writes:** rename updates `folders[].name`, move updates `folders[].parentId`, trash sets `status=trashed`, `trashedById`, and `trashedAt`, and restore sets `status=active`, clears the trash fields, and updates `parentId` when needed. Every edit stamps `updatedById` and `updatedAt`. Carry applicable retention to moved or relocated folders via the coverage writes below.
- [x] **Collaborators — invite and manage folder access.** Open **Manage access** from the folder header or row menu. List the owner, direct roles and statuses, and inherited access with its source folder. **Invite people** supports name/email suggestions, valid typed emails, an explicit role selector, and an optional message. Normalize email for matching, reject repeated direct invites, and allow multiple distinct recipients in one save. Existing directory users appear as active in this workspace. Other recipients appear pending. Change a direct role or confirm removal in the panel. Display inherited entries as read-only and direct users to the source folder. **Writes:** append one `collaborations` record per recipient with folder and actor IDs, `inviteeEmail`, optional `userId`, `role`, `message`, `status`, and timestamps. Role change updates `role` and update metadata. Removal sets `status=removed`, `removedAt`, `removedById`, and update metadata. Inherited access is derived.
- [x] **Tasks — create and manage file tasks.** File preview → Activity → **Add task** → General or Approval. Pick one or more people with active access to the file’s parent folder, including eligible inherited collaborators and its owner. Collect a message and optional due date, with an All assignees or Any assignee completion rule. Display the task beside the file and under Created by me in Task Center. Allow the creator to edit or delete while the task has no decisions. Reconcile edits to the assignee list without replacing unchanged assignments. **Writes:** append or update the `tasks` record and one `taskAssignments` record per assignee. Removed assignees and deleted tasks use the documented status transitions with actor and timestamps. Validate all choices before saving.
- [x] **Tasks — complete and review decisions.** Task Center shows Assigned to me and Created by me, status filters, due dates, and links to the relevant preview. Both views use the same mutation path. An assigned current user can mark a general task complete or approve/reject an approval task. Validate that the task and assignment are still open. Record that decision before recomputing the aggregate status using the completion rule in the data model. **Writes:** `taskAssignments[].status`, `decidedAt`, `decidedById`, and update metadata. Write `tasks[].status` and update metadata in the same transaction, plus `resolvedAt` and `resolvedById` when the task closes.
- [x] **Retention — create and start a policy.** Governance → Retention shows searchable policies with status, duration, folder count and disposition. **Create policy** collects name, description, Modifiable or Non-modifiable, finite/custom duration or Indefinite, Box creation date as the start basis, and disposition. Select one or more active folders in a searchable picker showing full paths, then review and confirm **Start policy**. A canceled or invalid form writes nothing. **Writes:** append an active `retentionPolicies` record with policy configuration, activation actor/time and creation/update metadata, plus one active `retentionAssignments` record per selected folder with policy/folder IDs and creation metadata. Detail and folder views reflect the selected and inherited coverage.
- [x] **Retention — apply, amend, and retire.** In policy details, add folders to an active policy and remove direct coverage from a modifiable active policy. Edit description, finite duration and disposition within policy-type rules. Confirm retirement and show retired policies in the status filter. A non-modifiable policy can add folders and extend a finite term, with shorter terms and folder removal unavailable. Indefinite duration remains indefinite. **Writes:** add or update `retentionAssignments` for direct coverage, update `retentionPolicies` settings and update metadata, and write `status=retired`, `retiredById`, and `retiredAt` at retirement. When a folder leaves a covered subtree by move or restore, add carried `retentionAssignments` for policies it would lose, linked to the original assignment. Show inherited and carried policies from their respective sources. Retired records remain inspectable. The workspace records disposition choices and keeps existing coverage visible without running any automatic jobs.
