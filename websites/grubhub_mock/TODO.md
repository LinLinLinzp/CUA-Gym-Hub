## P1 — Required Workflows

- [x] **Orders · find an order and inspect its receipt.** Show `All`, `Active` (placed and scheduled), and `Past` (delivered and cancelled), case-insensitive search over restaurant, item and order number, and a newest/oldest selector. Start newest first and paginate or reveal more after 12 cards. Each card shows restaurant, order number, date, concise item summary, status and total. `View receipt` opens line quantities, price breakdown, delivery address and masked payment. Offer `Reorder` on delivered orders, `Manage delivery` on upcoming scheduled orders and `Request a refund` on eligible delivered orders. Browsing and opening receipts write no record.
- [x] **Orders · create a delivery order or reorder.** Browse and search the local restaurant catalog, add menu items, edit line quantities, and choose a saved address and masked payment in checkout. `Reorder` opens a bag populated with available items from the previous order and sets `cart.sourceOrderId`. Confirm before replacing a bag from another restaurant. Each successful bag edit writes `cart` with item IDs, quantities, price snapshots, `updatedAt` and `updatedBy`. Checkout choices are drafts until confirmation. `Place order` with `ASAP` appends one `orders[]` record with ID, `status: 'placed'`, `fulfillment: 'delivery'`, `timing: 'asap'`, item quantities and amounts, totals, address/payment snapshots, optional `sourceOrderId`, `actorId` and `createdAt`. Clear `cart` in the same commit and open the receipt. Back, invalid input and repeated confirmation after the bag clears write no order.
- [x] **Scheduled delivery · book.** Offer `Schedule delivery` on the account schedule page and `Schedule for later` in checkout, including from a reorder. The account button opens checkout with scheduling selected if the bag contains items, or opens Browse restaurants in scheduling mode if the bag is empty. Pick an available day and 30-minute window from restaurant hours and the checkout clock. Confirm by pressing `Place scheduled order`. One commit appends `orders[]` with `status: 'scheduled'`, `timing: 'scheduled'` and `scheduledDeliveryId`, appends `scheduledDeliveries[]` with `orderId`, `status: 'scheduled'`, `windowStartAt`, `windowEndAt`, `timeZone`, `actorId`, `createdAt` and a `created` event, and clears `cart`. Land on the order receipt with the scheduled window visible. The account schedule view puts future deliveries first, linked to receipts.
  - [x] Keep scheduling mode when the diner uses the header links to browse or open the bag.
- [x] **Scheduled delivery · reschedule or cancel.** From the upcoming card or linked receipt, show the original window and open a focused date/time dialog. Enforce the eligibility rules in [the state model](assets/data_model.md#schedule-rules) at confirmation. Reschedule updates `scheduledDeliveries[].{windowStartAt,windowEndAt,updatedAt,updatedBy}` and appends a `rescheduled` event with old and new windows. Cancel requires confirmation, updates `scheduledDeliveries[].{status,cancelledAt,updatedAt,updatedBy}`, appends a `cancelled` event and updates the linked `orders[].{status,cancelledAt}` in the same commit. Closed dialogs, unavailable windows and ineligible attempts write no record.
- [x] **Refunds · request an item or full-order refund.** Start from an eligible receipt or choose an eligible order from the Refunds view. Present request scope, reason, optional details, and a checkable list of receipt lines with bounded quantities for an item request. Show the exact requested amount and masked original payment before `Submit request`. Append one `refunds[]` record with ID, `orderId`, `status: 'requested'`, `scope`, `reason`, optional `notes`, `lineItems[]` with `orderItemId`, `quantity` and `amount`, `amount`, `currency`, original payment snapshot, `actorId` and `createdAt`. Use remaining refundable units and the amount-allocation rule in [the state model](assets/data_model.md#refund-rules). Leave the order's fulfillment status intact. Reopen the case after reload, and show the associated request and remaining eligibility on the original receipt. Invalid and duplicate submissions write no record.
- [x] **Refunds · find and inspect a case.** Show case ID, linked order, restaurant, submission date, requested amount and status. Search for a restaurant, order number or case ID and filter by status. The case page shows the submitted reason, selected quantities and amounts, and a link to the source order. Derive labels from the saved request state and make browsing read-only.

## Verification and Acceptance

Use only `http://localhost:5317` or its loopback equivalent for functional tests. If starting a persistent server on Windows, run `Start-Process -WindowStyle Hidden` from the site directory and pass the resolved absolute `node_modules/vite/bin/vite.js` entry point to Node. Load Playwright from `PILOT_PLAYWRIGHT` and use the installed Chromium. Keep temporary runners and traces in ignored `test-results/`, or remove them when finished.

| Case | Expected UI and Harbor result |
| --- | --- |
| Order creation and reorder | Place an ASAP order and reload its receipt. Then reorder a seeded delivered receipt, edit its bag, and place the reorder. Check `orders` and `cart` writes, saved quantities and totals, the original order link, and a single order per confirmation. |
| Scheduled delivery | Book a future delivery from checkout, reschedule it, then cancel it. Check linked `orders` and `scheduledDeliveries` after each commit, including original/new windows, event timestamps, and cancellation on both records. Verify a confirmed delivery exposes no cancellation action. |
| Refunds | Request a refund for one unit of a multi-quantity line. Verify `refunds` contains that line, its quantity, original tender and computed amount. Reopen the case and test a second, full-order request against remaining amounts. Check invalid submissions and already reserved units cannot create duplicate refunds. |
| Runtime and layout | Use fresh session IDs for injection, cross-session isolation and hard reloads. Compare `/go?sid=<sid>` before and after user actions. Test empty arrays, missing optional fields, several hundred records, zero idle POSTs after baseline, and representative widths of `1440`, `1024`, and `390` px. Run `npm run build` and the repository's `factory/hub_tools/dyn_certify.py` against `grubhub_mock`. |
