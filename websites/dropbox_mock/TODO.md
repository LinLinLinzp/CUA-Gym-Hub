## P1 — Seed workflows

- [x] **P1.1 Files | Browse and preview.** Show sortable rows for name, modified, access and size. Open folders by name and show navigable breadcrumbs. Search active file/folder names across the tree, show locations in results, and filter by type. Preview files using seeded content or locally uploaded bytes. Browsing, search, sort and preview only read state.
- [x] **P1.2 Files | Create and upload.** Offer New folder and Upload files in the file toolbar, plus a file drop target when the file view is active. Trim names, reject invalid names and compare active sibling names case-insensitively. For a same-name file upload, confirm Replace or allow Keep both with a unique name. Use the same-origin Harbor `/upload` handler and commit successful bytes' metadata through the store. New folder writes `files[]`; new file writes `files[]` and an initial `versions[]` record; replacement writes a new `versions[]` record and updates the existing file's `currentVersionId`, `sizeBytes`, `mimeType`, `updatedAt` and `updatedBy`. Each action appends `activity[]`. Cancel and failed uploads leave account records untouched.
- [x] **P1.3 Files | Organize and recover.** Provide Rename, Move, Copy, and Delete in the row menu. Use a browsable destination picker and prevent moving into the source, its descendants or a conflicting name. Multi-select supports Move and Delete with all targets validated before committing. Rename writes `files[].name`; move writes `parentId`; copy creates new file/folder IDs and initial `versions[]` for copied files. Copies carry current content and start with their own sharing and history. Delete writes `status`, `deletedAt`, `deletedBy`, `deletionRootId` and recursively marks active descendants. Deleted files shows deletion roots, location and deleter. Restore clears deletion fields for that batch, retaining the original location if valid and allowing another destination if necessary. All actions stamp affected files and append structured `activity[]` with before/after values or source and destination IDs.
- [x] **P1.4 Sharing | Invite and manage access.** Open Share from Files, Preview, or Shared. Pick synthetic contacts or enter a valid email, set Can view or Can edit, and confirm. Show owner, direct members, and read-only inherited access from ancestors. Keep one membership per item/email, with explicit edit and remove controls. Invite appends or reactivates `shareMembers[]`; role change updates `role`; removal sets `status=removed` and `removedAt`. Stamp each changed record and append `activity[]`. Shared lists incoming and outgoing items using item ownership, active memberships and active links.
- [x] **P1.5 Sharing | Create and revoke a link.** From Share, create a scoped link and choose Anyone with the link, Team members, or Only people invited and Can view or Can edit. Show a selectable URL if clipboard access fails. Changing link settings updates `shareLinks[].audience` and `role`; generating creates an active record with a stable token; revoking changes `status` and sets `revokedAt`. These mutations stamp the record and append `activity[]`; copying an existing URL reads state. The local link route resolves only an active link to an active item, shows unavailable content for revoked/missing links, and respects simulated audience while rendering the preview.
- [x] **P1.6 File requests | Create, edit, close and reopen.** Use Open and Closed filters. List title, destination, submission count and status. Create with title, optional description and an active destination folder, then show the local recipient URL. Allow editing an open request's title, description and destination. Close with confirmation and reopen a closed request using the same token. Creation appends `fileRequests[]`; editing updates `title`, `description`, `destinationFolderId`; close/reopen update `status` and `closedAt`. Each mutation stamps the record and appends `activity[]`. Changing destination affects future submissions.
- [x] **P1.7 File requests | Receive and review.** Open the recipient URL in the same Harbor session. Accept submitter name, email and one or more local files for an open request with a valid destination. Save each submitted file with a unique name in that folder. Commit `requestSubmissions[]` (one record per file), `files[]`, `versions[]`, and `activity[]` together; derive the count and show uploaded filenames, uploader and time on the request detail page. Closed requests render an unavailable form and write nothing. Confirm success only after bytes are available locally and the account mutation is accepted by the store.
- [x] **P1.8 Versions | Inspect and restore.** Open Version history from an active file's menu or preview. Show newest first with date, author, size and a Current badge. Selecting a revision previews its specific content. Restore a historical version with confirmation, retaining the file ID, name, folder and permissions. Append a new `versions[]` record with `sourceVersionId`, update the file’s `currentVersionId` and content metadata, and append `activity[]` with previous, source and resulting version IDs. Keep the prior versions available. Disable restore for the current version.
