## P1 — Seed workflows

- [x] **Proposals — create and edit.** New document offers blank proposal or a template. Require a nonblank title. Creating writes one `documents[]` row with a fresh ID, optional template ID, title, company, currency, editable ordered sections, draft status, zero or copied value, ownership and timestamps. Copy template content by value. Support changing title, client, and section text in a draft. Save updates the draft fields and `updatedAt`. Duplicate from the register or detail into a fresh draft with regenerated owned child IDs, no recipient or signature history, and a recalculated value. Keep the source unchanged. Record create, save, and duplicate in `activity[]`.
- [x] **Proposals — recipients and delivery.** Add a saved contact as Signer or CC, reject duplicate recipients on the same proposal, and show recipient identity and role. A confirmed new contact writes `contacts[]`. Saving recipient changes writes `documents[].recipients`, `signingOrderEnabled`, and `updatedAt`, plus activity. Removing a recipient with assigned fields requires reassignment or removal of the fields in the same save. Review and send shows title, value, recipients, and field validation. Require a signer with a required Signature field per signer, and a valid assignment for every field. Send records `deliveries[]` with linked recipient IDs and optional subject/message, sets `documents[].status` to `sent`, sets `sentAt` and `updatedAt`, and appends activity. Display local signer links and keep sent/completed content read-only.
- [x] **Pricing tables — author and price.** Add a named table to a draft. Add a catalog item or named custom row, edit description, unit price, quantity, optional selection and recipient quantity permissions, and remove or reorder rows. Show computed line totals, subtotal, discount, tax, and total while editing. Save validates finite numbers and rules in the data model, writes nested `documents[].pricingTables` including line items and numeric calculated fields, recalculates document `value`, stamps `updatedAt`, and appends activity. A saved table has at least one line item. Confirmed table removal uses the same transaction and recalculates document value.
- [x] **Pricing tables — recipient choices.** In the signing route, a signer with assigned fields can toggle optional items and change quantities only where enabled. Recalculate a local preview. Finish commits changed `selected`, `quantity`, line and table totals, and document `value` with the signature and an activity record. Preserve an item-by-item choice snapshot on the signing completion record. After the first successful signing completion, present the accepted price read-only to other signers. An abandoned preview writes no state.
- [x] **Signatures — field placement.** Provide Add signature field, recipient dropdown, and section selection. Show assigned recipient and allow changing or removing an assignment before send. Explicit save updates `documents[].fields` with stable field, recipient and section IDs, field type and required flag, stamps `updatedAt`, and appends activity. Reject a deleted section or stale recipient reference at send. Signers should be able to locate required fields by both section and the signing panel.
- [x] **Signatures — sign and finish.** From a sent proposal, open the local recipient view, show the correct identity and eligible fields, and capture a typed signature with preview. CCs, later signers in a sequential flow, and completed signers see read-only states. Finish requires every required assigned signature to have a nonblank value. A successful transaction writes `signatures[]` per field and one `signingCompletions[]` record for the signer, sets recipient `status` and `completedAt`, stamps document `updatedAt`, and appends activity. Once all signers finish, set document `status` to `completed` and set `completedAt`. A partial finish retains `sent` or an existing `viewed` status. Revisit, refresh, repeated clicks, and stale attempts must not create duplicate signatures.
- [x] **Supporting libraries.** List and search templates by name and category, contacts by name/company/email, and catalog items by name/SKU/category. The template action starts the proposal creation flow. A selected contact or product stays local to the draft editor until the corresponding Save. Provide usable empty states and pagination on all three routes.
- [x] **Verification.** Run `npm run build`. Start Vite on localhost:5421 using PowerShell `Start-Process -WindowStyle Hidden` with the absolute Vite entry point and the target working directory. Use Chromium via `PILOT_PLAYWRIGHT`. From a fresh sid, create and edit a proposal, add custom and catalog pricing, assign fields to two signers, send, adjust eligible pricing and finish signer one, finish signer two, and confirm the final persisted records through `/go?sid=...`. Verify the intermediate states too, including price locks, blocked finish, reloads, isolated sids, injected data with empty/sparse/large arrays, and idle POST counts after boot. Use ignored or temporary runner files and document each tested workflow, result, and exact state fields in `TEST.md`. The parent runs Docker certification and handles commits.
