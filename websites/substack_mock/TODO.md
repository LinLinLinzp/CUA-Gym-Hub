## P1 — Required workflows

Every committed mutation below appends the named typed `events[]` record with actor, timestamp, related IDs, and action-specific fields defined in the [data model](assets/data_model.md). Group all changes for a confirmation in one save. Validation errors and cancellations leave state as-is.

- [x] **Posts · find and open.** Use Published, Drafts, and Scheduled tabs with counts. List title, optional thumbnail, author, state-appropriate date, audience, and available performance data. Provide search over title/subtitle, audience and tag filters, and date sorting. Rows link to the editor or reader view with a context menu. The active tab, search, filters, sort, and preview controls produce no persisted writes.
- [x] **Posts · create and edit.** From Create → Article or a draft row, open a focused editor with title, optional subtitle, and formatted body. Support basic heading, bold, italic, link, quote, and list controls and normal editing shortcuts. Offer Save draft, Preview, and Continue. Save or Continue commits a new `posts[]` record or updates `title`, `subtitle`, `bodyHtml`, changed settings, `updatedAt`, and `updatedById` on the existing record. Emit `post.created` or `post.updated`. Use the same ID and stable slug across edits and publication. Published edits use Save changes, preserve publication time and the original delivery timestamp, and update the web view. Preview supports web/email and audience, with Desktop/Mobile sizing. Preview unsaved edits from the editor without committing them. Use an in-editor preview when a new article has no ID yet.
- [x] **Posts · publish, schedule, and unschedule.** Continue opens review with audience, eligible comment permissions, tags, delivery checkbox, and optional local date/time. Require title and body to publish or schedule. Publish now writes `posts[].status=published`, `publishedAt`, clears `scheduledAt`, sets `deliveryAt` only for simulated email/app delivery, and saves `audience`, `commentPolicy`, `tags`, `sendByEmailAndApp`, `updatedAt`, and `updatedById` with `post.published`. Schedule writes those settings, `status=scheduled` and the ISO `scheduledAt` with `post.scheduled`. Validate a future date no more than three calendar months away. Editing the time emits another `post.scheduled` with the prior and new time. Unschedule restores `status=draft`, clears `scheduledAt`, and emits `post.unscheduled`. The scheduled row can be published by an explicit Publish now action. Advancing the clock alone produces no write.
- [x] **Posts · duplicate and delete.** Duplicate to drafts creates a new `posts[]` record with a fresh ID/slug, `duplicatedFromId`, draft status, and cleared publication, delivery, and deletion times and metrics. Emit `post.duplicated`. Confirm deletion for a draft, scheduled, or published post. Write `status=deleted`, `deletedAt`, `updatedAt`, and `updatedById` plus `post.deleted`. Exclude deleted posts from lists and reader access while retaining the tombstone and comment links.
- [x] **Subscribers · find, filter, and inspect.** Show summary counts above a checkbox table with Subscriber, Type, Start date, Activity, Revenue, and row actions. Search by name/email. Combine type, joined date, and activity filters. Sort by visible sortable columns and paginate at 50 rows with a separate affordance to select all matching results. Open the subscriber detail with type/status, source, activity, attached comments, and event history. Clear the selection when search/filter scope changes. Browsing and selection produce no persisted writes.
- [x] **Subscribers · add or import.** Add subscribers accepts one or more email addresses or a locally parsed CSV with an email header and optional name. Show accepted and rejected rows before confirmation, normalize case and whitespace, and detect duplicates in the batch and publication. Accept the valid unique rows and show counts and rejection reasons. Default to Free subscription, optionally select a trial duration and record the welcome email checkbox. Append `subscribers[]` records with `source=manual|csv`, `status=active`, `baseType=free|trial`, `joinedAt`, `trialEndsAt`, `welcomeEmailRequestedAt`, and creation metadata. Append `subscriber.added` with the accepted IDs and quantity.
- [x] **Subscribers · remove.** Expose Remove from the detail and selection menus with confirmation and affected count. Set `subscribers[].status=removed`, `removedAt`, `removedById`, `updatedAt`, and `updatedById` for each selected active ID. End its non-ended grants with the same revocation fields used by End comp and record their IDs in `subscriber.removed`. Drop removed records from the active list. For paid rows with complete billing data, show the simulated prorated amount in confirmation and include the amount and currency in the event; omit refunds when billing data is incomplete.
- [x] **Subscribers · export.** Offer all subscribers or the filtered results, and display columns or all supported columns. Export the active rows in the chosen scope as a local CSV with headers, quoted values, and deterministic row order matching the visible sort. Append `subscriber.exported` with row IDs, scope, columns, quantity, and filename when the download is triggered.
- [x] **Comp subscriptions · grant and extend.** Open Comp from a subscriber row/detail or a bulk selection. Dialog shows affected count and dates or timing, duration options of 7 days, 30 days, 90 days, 6 months, 1 year, or forever, and an optional Set to Founding checkbox. Confirm to add one `compSubscriptions[]` record per selected active subscriber. A new comp starts now or at the subscriber's future paid-through or trial-end date, whichever applies. Extend an existing finite grant from its current end by updating `endsAt`, `duration`, `tier` if changed, `updatedAt`, and `updatedById`, with `comp.extended`. Each new record and its `comp.granted` event includes linked subscriber, actor, duration, start/end, tier, zero amount, currency, and current timestamp. Show current or upcoming comp in the detail and make active comp filterable in the list. No-op confirmation for an existing forever grant must not create duplicate grants or events.
- [x] **Comp subscriptions · end.** Provide End comp on a subscriber detail with a current or upcoming grant and confirm the outcome. Set `compSubscriptions[].status=revoked`, `revokedAt`, `revokedById`, `updatedAt`, and `updatedById` and emit `comp.revoked` with the grant and subscriber IDs. Derive current access from grant dates and remaining base access. Ending a comp preserves subscriber membership and any paid time still in force.
- [x] **Comments · post and reply.** Render a publication archive and an article view with a comment count and a discussion thread under published posts. Render author, timestamp, body, Reply, and menu with nested replies. Enforce publication and post permissions and trim and reject empty bodies. Submitting adds `comments[]` with `postId`, `parentId` (null for a new top-level comment), `authorId`, `body`, `status=visible`, `reviewStatus=none`, `createdAt`, and `updatedAt`. Emit `comment.created` with both IDs and parent when present. Link directly to comments from Posts and subscriber detail.
- [x] **Comments · pin, remove, and review.** Publisher comment menus provide Pin/Unpin and Remove with confirmation; multiple visible top-level comments can be pinned. Write `pinnedAt`, `pinnedById`, and `updatedAt` with `comment.pinned` / `comment.unpinned`. Confirmed removal writes `status=removed`, clears pin fields, sets `moderatedAt`, `moderatedById`, and `updatedAt`, and emits `comment.removed`. Moderation shows Reported, Approved, Removed, and Hidden tabs with post links and available report reasons. Approve a reported comment by writing `reviewStatus=approved` and moderation metadata with `comment.approved`. Removing a reported comment also sets `reviewStatus=removed`. Unhide a seeded hidden comment by setting `status=visible` and moderation metadata with `comment.unhidden`. Display a placeholder parent when visible replies survive a removal. Collapse/expand a branch without writes.
- [x] **Comments · configure access.** In Settings → Community, expose the publication toggle for comments and save to `publication.commentsEnabled`, `updatedAt`, and `updatedById` with `publication.commentsChanged`. Post settings exposes Everyone, Subscribers, Paid subscribers, Founding members, and No one as allowed by audience. When an audience change invalidates the selected permission, show the required replacement before save. Committing a policy change updates the existing post through the same `post.updated` or publish/schedule operation. Disabling comments closes the composer and preserves existing discussion history.
