## P1 — Required workflows

- [x] **FAFSA — start, save, submit.** Show forms by award year with status filters and search, group revisions into a single current entry per year, and expose historical versions from the detail view. Start by choosing an unused supported award year, or route to the existing active edition for that year. Build a resumable wizard with Student information, Financial information, Schools, and Review & sign. Include synthetic student/contributor consent and signature controls, dependency choice, a searchable school picker with remove controls, inline validation, and numbered progress. `Start form` creates a `fafsaForms[]` record (`status: draft`, `awardYear`, `revision: 1`, `actorId`, timestamps). `Save and continue` and `Save and exit` update `answers`, `schoolIds`, `contributors`, `lastSavedStep`, and `updatedAt`; the same draft resumes by ID after reload. `Submit FAFSA` validates complete answers, at least one school, consent, and all required signatures before setting `status: in_review`, `submittedAt`, `updatedAt`, and the saved full form on the same record. Show a receipt that links to My Activity. A submitted form stays in review until a supplied scenario provides a processed record.
- [x] **FAFSA — review and correct.** From My Activity or a processed form, show eligibility estimate (when supplied), reported answers, schools, and next steps. Offer `Make a correction` for a processed or action-required latest edition. It appends a `fafsaForms[]` draft with the same `groupId`, incremented `revision`, `previousFormId`, copied answers/schools/contributors, reset signatures, `actorId`, and timestamps. Continue editing and submit via the same wizard. Maintain the prior edition and its summary, and return to an existing correction draft on repeated entry.
- [x] **Loans — find, inspect, acknowledge.** Show outstanding principal and accrued interest, loan status and servicer filters, school/type/ID search, and balance or disbursement sorting. Loan detail shows school, type, disbursement, original amount, principal, interest, rate, current plan and servicer, with a repayment link. From the list, open `Annual Student Loan Acknowledgment`; choose an award year, review all loans with positive balances and their aggregate balance, and sign the acknowledgment. Confirmation appends `loanAcknowledgments[]` with `status: completed`, `awardYear`, `loanIds`, `loanCount`, balance snapshot, `actorId`, and signed/creation timestamps. Show the result in My Activity, reopen it after reload, and reuse the receipt if already signed for the same year. Loan balances and plan terms come from `loans[]` and `servicers[]`.
- [x] **Repayment plans — compare and save estimates.** Load active loans from My Loans and support selecting a subset. Accept annual income, family size, and optional scenario name. Compare eligible sample plans using estimated monthly amount, total paid, and term, with sort controls and ineligible explanations. Use deterministic estimate logic, include a fixed-rate amortization baseline with a zero-rate branch, and label all outputs as estimates. `Save comparison` appends `repaymentScenarios[]` with selected `loanIds`, `loanCount`, `inputs`, `estimates[]` keyed by `planId`, `status: saved`, `actorId`, and `createdAt`. The saved list opens the original snapshot after reload, including if a related loan or plan is absent from injected data.
- [x] **Repayment plans — apply and track.** From an eligible income-driven plan or a saved comparison, start a request and choose a single servicer cohort if multiple servicers are present. Confirm selected loans, optionally prefill income and family size from the comparison, gather request type and synthetic income consent, and review/sign. `Start request` appends `repaymentRequests[]` with `status: draft`, `planId`, `loanIds`, `servicerId`, optional `scenarioId`, `actorId`, and timestamps. Saving updates `requestType`, `inputs`, `lastSavedStep`, `updatedAt`. Valid submission adds `signedAt`, `submittedAt`, saves the reviewed fields on the same request, and sets `status: in_review`. My Activity shows status and serves as another resume/view entry. Application submission records a request for review. Display the loan’s enrolled plan using the current loan record.
- [x] **Account overview and activity.** Overview links to the current FAFSA summary/resume, loan balance/details, and repayment comparison; show recent activity with dates and status. My Activity derives its list from FAFSA editions, acknowledgment receipts and repayment requests. Filter by type and status, and sort latest update first. Deep-link to each record so testers can check stored status independently of the wizard. Distinguish no data from no matches and provide a clear-filter action.
- [x] **Local acceptance and handoff.** Run `npm run build` and use the installed Node Playwright from `PILOT_PLAYWRIGHT` with Chromium on `localhost:5518`. Start the persistent dev server via `Start-Process -WindowStyle Hidden` with the absolute Vite entry point and the target site as working directory. Use fresh `sid`s for default and injected scenarios. Exercise FAFSA draft/reload/submit and processed correction, loan filters/detail and signed acknowledgment, repayment comparison/save/reload/request, direct-route reloads and session preservation. Assert exact record fields and `state_diff` per action through `/go`. Watch for console errors, unexpected remote network or idle `set_current` POSTs, and cover empty, minimal and large injected worlds. Remove scratch files or keep them under a gitignored site path. Record commands, results and changed state fields in `TEST.md` for the parent runner’s Docker certification and commit.

## P2 — Secondary features

The three required workflows and their shared activity views define this phase’s scope.

## Data seed

- [x] Supply 24 FAFSA editions grouped across eight award years, 30 searchable schools, 24 loan records over a believable multi-program borrowing history, 24 saved comparison scenarios and 24 repayment requests across historical and active statuses. Use a small reference set of plans and servicers, and seed illustrative signed acknowledgments. Keep cross-references valid and IDs and dates fixed. Keep the newest supported FAFSA year free and the newest historical processed year available for corrections. See [the data model](assets/data_model.md) for the fixture mix and fallbacks.

## Out of scope

Authentication, real identity verification or signatures, tax-data retrieval, billing and payments, messages to contributors or servicers, external account integrations, and unrelated aid programs. Use local synthetic consent and signature records to exercise the form flows.
