## P1 — Seed workflows and state writes

Every successful update to an existing business record stamps `updatedAt` and `updatedBy`. New records receive fixed-shape IDs, actor fields and ISO timestamps as defined in the [data model](assets/data_model.md). Each permanent deletion appends an `activity` record, and each moderation action appends a comment activity record. Errors, cancelled interactions and unchanged saves leave state untouched.

- [x] **P1.1 · Posts list and quick actions.** Show title, status, author, categories, tags, comment count and date. Expose All, Published, Drafts, Pending, Scheduled, Private and Trash filters, search, month and category filters, title/date sorting, pagination, and row or keyboard-accessible menu actions. Keep selection page-scoped and clear it when the result set changes. Quick Edit exposes title, slug, author, categories, tags, visibility/status and comments, with Update and Cancel. Bulk Edit applies only chosen fields to selected rows, and bulk trash, restore and confirmed permanent delete follow the same transitions as individual actions. Open the editor from the title and the moderation list from the comment count. **Writes** — Quick Edit and Bulk Edit update applicable `posts[]` fields (`title`, `slug`, `authorId`, `categoryIds`, `tagIds`, `status`, `commentsOpen`, publication timestamps and update stamps). Lifecycle writes follow P1.4.
- [x] **P1.2 · Posts editor and publishing.** Provide a title, ordered paragraph, heading, list, image and quote blocks, and an inserter with move/remove actions and keyboard access. Show Post and Block settings, with slug, excerpt, author, Categories, Tags, Featured image, Discussion, status and publish date on Post. Reuse the Media Library for image and featured-image selection. Keep changes local until Save draft, Submit for review, confirmed Publish, Schedule or Update. Offer a local preview of the current draft, prompt on leaving dirty edits, and show the saved status and date after the commit. Validate an explicit future date for Schedule, use UTC for date input and display, and keep the scheduled status observable until a user explicitly changes it. Changing a scheduled item to draft clears its schedule. **Writes** — insert or update `posts[]` with `title`, `slug`, `blocks`, `excerpt`, `authorId`, `categoryIds`, `tagIds`, `featuredImageId`, `commentsOpen`, `status`, `scheduledAt` and `publishedAt`; create any newly entered category/tag in `categories[]` or `tags[]` with the corresponding post links in the same commit.
- [x] **P1.3 · Pages list, editor and hierarchy.** Give Pages its own searchable status-filtered table with author, date, sortable title and page order. Display the parent under child titles and expose Parent and Order in Page settings and Quick Edit. Support single and bulk settings updates, reject self-parenting and cycles, and provide a top-level choice. Use the shared block editor, preview and draft/review/publish/schedule/update controls. Open the saved page preview from its row. **Writes** — create or update `pages[]` with `title`, `slug`, `blocks`, `excerpt`, `authorId`, `featuredImageId`, `commentsOpen`, `status`, `scheduledAt`, `publishedAt`, `parentId` and integer `menuOrder`. Bulk edits update selected pages' applicable `authorId`, `parentId`, `status`, `commentsOpen` and publication timestamps. Quick Edit also supports `title`, `slug` and `menuOrder`. Lifecycle writes follow P1.4.
- [x] **P1.4 · Post and page trash and recovery.** From either content table or editor, Move to Trash changes list membership immediately and shows a confirmation notice. Restore from Trash returns content to Drafts with its ID and editable fields intact. Expose Delete permanently in Trash and confirm the selected records before removal. **Writes** — trash updates `posts[]` or `pages[]` to `status: "trash"`, sets `trashedAt` and clears `scheduledAt`; restore sets `status: "draft"` and clears `publishedAt`, `scheduledAt` and `trashedAt`. Permanent delete removes the selected rows and their `comments[]`, adds one `activity[]` record per removed content row with its related comment IDs, clears matching `media[].uploadedTo`, and sets surviving direct child `pages[].parentId` to `null` when deleting a parent page.
- [x] **P1.5 · Media Library, upload and metadata.** Offer grid and list views, search by title/filename/alt text, filters by file type and upload month, and an Unattached filter. Include a multi-file input and a drop zone. Upload accepted images, PDFs, audio and video through the standard same-origin multipart `/upload` endpoint with the session. Use response file URLs and byte counts. Commit one `media[]` row per successful file, report per-file failures, and allow retry of failed files. Store URLs and metadata in state. Preview local file types safely and fall back to a named file tile if a preview fails. Open details from grid or list with file name, type, byte size, date and an accessible form for title, alt text, caption and description. **Writes** — upload inserts `media[]` rows with `id`, `fileName`, `url`, `mimeType`, `sizeBytes`, `width`, `height`, `title`, `altText`, `caption`, `description`, `uploadedTo`, author and timestamps. Details Save updates `title`, `altText`, `caption`, `description` and update stamps.
- [x] **P1.6 · Media reuse, attachment and deletion.** Provide a searchable Attach to existing content dialog and a Detach action in list view. In the post/page editor, selecting a library image stages an image block or featured image until the document is saved. Attachment ownership and content usage have separate controls. Confirm individual or bulk Delete permanently, identifying affected content wherever possible. **Writes** — Attach/Detach sets `media[].uploadedTo` to `{type, id}` or `null`; document Save writes an image block's `mediaId` or `posts[].featuredImageId` / `pages[].featuredImageId`. Permanent delete removes `media[]` rows, appends `activity[]` entries with related content IDs, clears matching featured-image IDs and sets matching image-block `mediaId` to `null` while retaining the block caption. All affected records commit together.
- [x] **P1.7 · Comments queue and moderation.** Show All (pending and approved), Mine, Pending, Approved, Spam and Trash tabs with counts, search across author/text/content title, sorting by date, author or target, and a link back to the owning content. Highlight pending comments and show actions available for each current status. Approve/Unapprove changes visibility; Spam and Trash move to their queues; Not Spam and Restore recover the prior active status; confirm Delete Permanently in Spam/Trash. Expose corresponding bulk actions with selection and Apply. Show feedback and recompute queue counts and preview visibility immediately. **Writes** — update `comments[].status`, `priorStatus` and update stamps, or remove the row and reconnect surviving direct replies to its nearest surviving ancestor. Append one `activity[]` row per affected comment with `action`, `targetId`, content link, `fromStatus`, `toStatus`, `actorId` and `createdAt`.
- [x] **P1.8 · Comment reply, edit and history.** Open an inline Reply or Quick Edit form from the row. Reply to an approved comment or use Approve and Reply on a pending comment. Cancel or validate before saving. History shows persisted events for the selected comment. Saved content previews show approved comments under live approved ancestors. **Writes** — Reply inserts an approved `comments[]` record with `parentId`, `contentType`, `contentId`, signed-in commenter identity and timestamps, plus a `comment_replied` activity event. Approve and Reply also updates the parent and adds a `comment_approved` event in the same commit. Quick Edit saves `body`, `authorName` and/or `authorEmail` and update stamps, plus a `comment_edited` event.
