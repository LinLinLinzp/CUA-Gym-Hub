## P1 — Primary Workflows

- [x] **Sheets — create, rename, favorite, and delete.** Create → Sheet opens a dialog for name, workspace, and Blank Sheet or Project Sheet. The Project Sheet preset includes the Gantt column mappings; create opens the new grid. Rename through the title menu. Delete asks for confirmation and hides the sheet from Browse, Search, and Favorites. **Writes:** create appends `sheets[]` with typed `columns[]`, workspace and owner IDs, `status: active`, and metadata. Rename changes `sheets[].name` and update metadata. Delete marks `sheets[].status: deleted`, records `deletedAt` and `deletedBy` plus update metadata, removes its ID from `preferences.favoriteSheetIds`, and cancels its pending `approvalRequests[]`. Linked rows, forms, submissions, and prior decisions remain readable as records in `/go`.
- [x] **Sheets — grid and typed editing.** Build sticky headers, row numbers, an Add Row control, and a column menu. Click selects, double-click or Enter edits, Enter/Tab commits and advances, and Escape cancels. Provide text, number, date, dropdown, contact, checkbox, and percentage editors plus the project-specific duration and predecessor editors. Row menu inserts above/below or deletes selected rows with confirmation. Column menu adds, renames, and reorders columns while keeping IDs stable. Column types and numeric/date formats are specified in [the data model](assets/data_model.md). **Writes:** row insertion appends `rows[]` with `sheetId`, `position`, `cells`, `source: grid`, `status: active`, and metadata, and writes updated positions and metadata to displaced rows. Cell edits write `rows[].cells[columnId]` and row update metadata. Row deletion records `status: deleted`, `deletedAt`, and `deletedBy` plus update metadata, cancels pending requests for that row, and validates active dependent rows before committing. Column edits update `sheets[].columns[]` and sheet update metadata. Row changes bump the parent sheet’s update metadata and evaluate applicable approval rules on eligible edits and creates.
- [x] **Sheets — filter and sort.** Filter by column with typed `equals`, `contains`, and `is blank` operators where applicable. Apply and clear the filter on Grid or Gantt, using the same visible row IDs in both. A column menu offers ascending and descending sort; sort over all active rows after clearing the filter, with stable ties. **Writes:** sort updates the active rows’ `position` values and update metadata for changed rows, plus sheet update metadata. Filtering is transient.
- [x] **Forms — manage and build.** Use the Forms sheet action to list forms and open the builder. Create a form from the sheet’s typed columns; add, remove, or reorder fields, edit each label/help text, toggle Required or Hidden, set typed defaults, and edit the title, description, confirmation message and row placement. Preview the draft with the same rendering and validation as the public form. Copy the public URL for an active saved form. Support edit and deactivate/reactivate in the list. **Writes:** Save creates or updates `forms[]` with `sheetId`, `title`, `description`, ordered `fields[]`, `confirmationMessage`, `rowPlacement`, `status`, and metadata. Deactivate/reactivate updates `status` and update metadata. Opening previews and copying URLs leave state unchanged.
- [x] **Forms — submit and trace to the sheet.** On `/forms/:formId`, render saved fields in order with their appropriate controls and inline errors. Honor hidden defaults and required visible fields. Disable repeat submit while committing and show the saved confirmation after success. A newly submitted row appears at the configured end of the same sheet with the exact typed values. **Writes:** append `formSubmissions[]` with `id`, `formId`, `sheetId`, `rowId`, `values`, `status: submitted`, `createdAt`, and `createdBy`. Append `rows[]` with the same values initially in `cells`, `source: form`, `formSubmissionId`, `position`, and row metadata. Update positions and metadata for displaced rows, plus sheet metadata. Evaluate row-added creation rules in the same commit and keep submitted values as a snapshot even if approval or later edits change the row.
- [x] **Approvals — configure an automation rule.** Use Automation → Manage Workflows or Create Workflow. The builder names a rule, selects Row added or Row changed, sets a watched column for Row changed, optionally applies one typed equality condition, selects a contact, and chooses a dropdown column for the response. Allow custom subject/message and pause or reactivate. Validate the chosen column can hold `Submitted`, `Approved`, and `Declined`, offering to create the standard dropdown when needed. **Writes:** create or update `approvalWorkflows[]` with `sheetId`, `status`, `trigger`, `condition`, `approverId`, `responseColumnId`, `subject`, `message`, and metadata. Creating the response column also updates `sheets[].columns` and sheet update metadata.
- [x] **Approvals — trigger and respond.** Run active rules as part of explicit matching sheet or form commits. Create no more than one request per workflow and row. Request details open from Notifications → Requests or a deep link and show status, requester, subject/message, sheet, and the row context. The recipient can Approve or Decline with an optional note; repeat or ineligible responses leave records unchanged. **Writes:** trigger appends `approvalRequests[]` with linked workflow/sheet/row IDs, approver/requester IDs, the response column and message snapshot, `status: pending`, and `createdAt`; it also writes `Submitted` to the selected row cell. Mark as read writes `readAt`/`readBy` on the request. Approve/decline writes request `status`, `respondedAt`, `respondedBy`, and `responseNote`, sets read metadata if needed, updates the response cell to `Approved` or `Declined`, and stamps row and sheet metadata. Cancellation on deletion writes `status: canceled`, `canceledAt`, and `canceledBy` on pending requests.
- [x] **Gantt — configure and inspect the schedule.** Add visible Grid/Gantt tabs, a synchronized split grid and timeline, task bars, milestone diamonds, dependency connectors, percent fills, day/week/month/quarter zoom, and Project Settings. The settings dialog maps start and end date columns and optional percentage column. Enabling dependencies requires duration and predecessor columns and working weekdays/holidays; offer to create missing mapped columns in the same Save. **Writes:** settings Save updates `sheets[].projectSettings`, `sheets[].columns` if new columns were added, sheet update metadata, and any `rows[].cells` and row metadata changed by schedule recalculation. View changes, zoom, scrolling, and the divider are transient.
- [x] **Gantt — edit dates, progress, and predecessors.** Move or resize bars with keyboard-accessible date cells as an equivalent path. Commit drag on drop, snap to day boundaries, and show start/end in the drag preview. Use the same typed cells in both views. Enable `Finish-to-Start` dependencies with workday lag, recalculate affected successors once, and clearly reject self-links, cycles, missing references, and invalid ranges. A dependency-controlled start date is edited through its predecessors; a dependency-enabled milestone is a zero-day task. **Writes:** edits write the mapped start, end, duration, predecessor, or percentage values to `rows[].cells` for the directly edited and affected rows, plus row and sheet update metadata. Directly edited cells can match approval rules; calculated cells and approval-status writes never trigger further rules. The exact date and dependency rules are in [the data model](assets/data_model.md).
