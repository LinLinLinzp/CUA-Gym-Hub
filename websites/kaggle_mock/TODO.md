## P1 — Seed workflows

- [x] **Competitions.** Search by title, summary or category. Filter by category and Open, Closed or Joined, and sort by deadline or teams. Cards show type, host, metric and deadline. Detail tabs show Overview, Data, Rules, Leaderboard and My Submissions. Show the applicable rules revision and require an explicit Accept Rules confirmation before allowing competition data downloads or submissions. Acceptance adds `competitionEntries[]` with `id, competitionId, actorId, rulesVersion, status, createdAt`. Show Joined after reload and reject repeat acceptance for the same revision. Joined users can download available files, each adding a `downloads[]` record for the competition and file. An open joined competition accepts a local CSV and optional description after validation; add `competitionSubmissions[]` with `id, competitionId, entryId, actorId, file, description, status, score, createdAt`. Show the result in My Submissions after reload. Use deterministic sample scoring on submit and derive the user's best score for the leaderboard without changing seeded community rows. Disable participation actions when closed and explain the unavailable action. Opening tabs, sorting, and toggling filters write no records.
- [x] **Notebooks.** Search by title, owner or tag, filter by language or My Notebooks, and sort by votes or update time. Show notebook metadata, saved cells and version history on the detail page. New Notebook creates an owned private draft with a starter cell. Copy & Edit creates a separate private draft using the selected source's saved cells, with `forkedFromId` set and the original intact. Both write `notebooks[]` with ownership, visibility, draft contents and timestamps. In the editor let owners rename the notebook, edit/add/reorder/remove code and Markdown cells, and select a dataset input from accessible datasets. Save Draft writes title/cells/input IDs, `updatedAt`, and a `notebookDraftSaves[]` record. Save Version also appends `notebookVersions[]` with `notebookId, actorId, number, title, cells, datasetIds, message, createdAt` and updates the notebook's `latestVersionId`. Allow selecting earlier immutable snapshots and show current visibility. Public/private confirmation updates the notebook and adds `visibilityChanges[]`. Preserve the route slug when renaming. Use static or locally generated example outputs. Browsing a notebook or editing an unsaved form writes no records.
- [x] **Datasets.** Search titles, owners and tags. Filter by license, file type or My Datasets and sort by update time or downloads. Details show description, license, current version, file list and an offline preview where available. Download File saves `downloads[]` with the dataset, file and version. New Dataset collects title, description, license, visibility and one or more local files. Create a `datasets[]` record and corresponding `datasetVersions[]` version 1, with file metadata and local URLs. Owner Edit Details saves metadata and appends `datasetEdits[]`; a visibility change also adds a `visibilityChanges[]` entry. New Version submits replacement files and release notes, appends a version with `id, datasetId, actorId, number, files, notes, createdAt` and updates the parent `latestVersionId, updatedAt`. Keep previous versions downloadable. New Notebook from a dataset creates an owned private notebook with that dataset ID preselected. Browsing files and switching history versions write no records.
- [x] **Validation and verifier handoff.** Require nonblank titles, valid file selection, license on dataset creation, and a confirm action for state mutations. Use same-origin `/upload` for user-selected files and scoped downloads. Failed validation and failed uploads do not create business records. Keep SCHEMA.md synchronized with all top-level keys and the exact action-to-field mapping in the data model. Test all three workflow write paths via `/go?sid=…` after reload, verify scope isolation with distinct SIDs, and verify idle tabs do not post. Include default, injected empty, sparse and large-world routes in local checks. Record results, actions and observed fields in TEST.md; the parent runner handles Docker certification and commits.
