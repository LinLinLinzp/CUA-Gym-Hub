## P1 — Required workflows

- [x] **Uploads.** On Upload, provide a labelled file picker and drop zone, title input prefilled from the filename, optional genre/tags/description, and Public/Private selection. Validate a nonempty supported audio file and a trimmed title. On Publish track, submit the audio as multipart to `withSid('/upload')`; use the returned file metadata, and show an actionable retry message if it fails. Disable repeated submission while pending. On success append one `uploads` record and one linked `tracks` record in the same state write, with IDs, current actor, UTC timestamps, published status, file metadata on the upload, and submitted metadata plus visibility on the track. Open the new track detail, and show it in Tracks after reload. Track detail exposes Edit details for tracks owned by the account. Saving updates metadata, privacy, `updatedBy`, and `updatedAt` on that track. Cancel preserves the original values.
- [x] **Playlists.** Show a searchable Playlists list with visibility filtering and track counts. Create a playlist from this list or from a track's Add to playlist action. Require a trimmed title; allow description and Public/Private selection. On detail provide Add tracks with title/artist search, move up/down buttons, Remove, and Save changes. Disable duplicate additions and boundary moves. Creation appends a `playlists` record, and each successful edit updates its metadata or ordered `trackIds` with `updatedBy` and `updatedAt`. Adding from track detail appends the track to that playlist after explicit confirmation and updates the same fields. Playlist privacy changes leave track visibility intact.
- [x] **Comments.** Track detail shows a waveform timeline, a composer, and active comments with author and optional audio position. Selecting a position supplies integer seconds for the next comment; an untimed comment uses null. Support replies, inheriting the parent's timestamp, and reject blank text. The Comments inbox on the account’s tracks links to the relevant track and offers track filtering. Posting or replying appends a `comments` record with author, track, optional parent and offset, status, body, and UTC creation time. Allow the author or track owner to confirm removal, then write `status: 'deleted'`, `deletedBy`, and `deletedAt` on the record. Hide its body in the UI and keep active replies visible. Show meaningful states for an empty inbox and for no comments on a track.
- [x] **Stats.** Insights shows Plays, Likes, Comments, Reposts and Downloads from `dailyStats` for the active creator's tracks. Filters offer all/one track, a 7/30-day reporting period or custom UTC bounds, and one metric for the chart and track ranking. Start with the latest 30 recorded calendar days, displaying the exact dates; use the current UTC date as the end date when there are no recorded days. Preview dates and scope in the filter controls. Apply validates the selection and appends an `insightViews` record with actor, metric, track or null, exact applied bounds, result count, calculated metric total and UTC timestamp. Reload restores the actor's most recent valid applied selection. A zero-result range still records a successful Apply with zero totals. First render, hover, navigation, and sample data create no views; playback and comments leave the historical `dailyStats` rows intact.
- [x] **Browser acceptance.** Exercise upload and track edit, playlist create/add/reorder/remove, comment/reply/remove, and insights filtering through the visible UI at `http://localhost:5357`. Use installed Node Playwright from `PILOT_PLAYWRIGHT` and Chromium. For each workflow assert the relevant `/go?sid=…` records and check reload persistence. Also check SID isolation, an injected empty world, one partial-record world, direct routes, validation/cancel paths, and idle POST behavior. Start any persistent server with `Start-Process -WindowStyle Hidden` and an absolute Vite entry point. Keep scratch files gitignored or remove them. Summarize results and exact changed fields in `TEST.md`; the parent runner handles Docker certification and commits.
