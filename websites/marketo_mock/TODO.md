## P1 — Required workflows

- [x] **Programs — create and manage a marketing initiative.** Show a table with Name, Type, Channel, Folder, Members and Updated. Add case-insensitive search, type and channel filters and sortable columns. `New program` requires a unique name within a folder, folder, type and compatible channel. Allow an optional description. Open the saved program with Overview, Members and Assets tabs. Edit name and description from Overview. Archive or restore from the action menu with confirmation, retaining member and asset links. **Writes:** create `programs[]` with `id`, `folderId`, `name`, `type`, `channel`, `description`, `status: 'active'`, creation/update metadata. Edit changes `name`, `description` and update metadata. Archive or restore changes `status` and update metadata. Each committed action appends `activityLog[]` with the program ID and action.
- [x] **Programs — manage member participation.** In Members, provide a searchable person picker with checkboxes, show member status per person, and offer `Change status` for selected members. Use the program channel's valid statuses and derive success counts from those statuses. Skip duplicate membership and unchanged statuses. **Writes:** add or update `programMembers[]` by `programId` and `personId` with `status` and creation/update metadata. Add one activity entry per bulk action with changed person IDs and quantity. Do not modify `people[]`.
- [x] **Lists — create and maintain a static list.** Include list name, kind, scope, people count and updated columns with search, kind/scope filters and sorting. `New list` takes name, kind, scope (Database or Program), owning program when scoped and optional description. Details allow metadata edits. The static People tab supports bulk add from the searchable database, row selection and confirmed `Remove from list`. Removing a person retains their database record and other list memberships. **Writes:** create `lists[]` with `id`, `name`, `kind: 'static'`, `programId`, description and metadata, or update name/description and update metadata. Add/remove `listMembers[]` scoped by `listId` and `personId`, update the list timestamp on actual membership changes, and append an `activityLog[]` entry with changed IDs and quantity.
- [x] **Lists — build and preview a smart list.** Use the same New list entry and give Smart List and People tabs. Support Country, Company, Lifecycle stage, and Member of static list rules, with field-appropriate operators. Offer All, Any and an explicit All people option. Preview and People use the same matcher. Allow rule removal and Cancel without writes. Save a valid config and show the resulting count and member table immediately. **Writes:** create `lists[]` with `kind: 'smart'` and an initially null `matchMode`. Rule saves change `matchMode`, `rules[]` and update metadata and append `activityLog[]`. Smart membership is derived from `people[]` and `listMembers[]`.
- [x] **Smart Campaigns — create and configure automation.** Show Name, Program, Mode, Status and Updated with text search, filters and sortable columns. `New smart campaign` requires an owning program and unique name within it. Details expose Smart List, Flow, Schedule and Results. Share the lists rule editor. Allow a `Person is created` or `Added to list` trigger, with a static list required for the latter. Any configured trigger sets campaign mode to Trigger. Flow supports ordered Add to List, Remove from List and Change Program Status steps. Use local selectors for valid target IDs and status, and provide keyboard-accessible Move up/Move down. Save trigger/filter and flow edits explicitly. Active Trigger and scheduled Batch campaigns must be deactivated or canceled before changing configuration. **Writes:** create `smartCampaigns[]` in Draft with `programId`, name, description, default Batch mode and metadata. Smart List saves `matchMode`, `triggers[]`, `rules[]`, derived `mode` and update metadata. Flow saves `flow[]` and update metadata. Append `activityLog[]` for each saved change.
- [x] **Smart Campaigns — run, schedule and activate.** Schedule shows qualification count and validates the saved Smart List configuration and Flow. Batch offers `Run once` with `Run now` or a future date/time, plus `Cancel run` when scheduled. Confirmed immediate runs apply the ordered flow locally to the matching people and display a Results row with processed count and step outcomes. Future schedules store a dated run record and appear on the Schedule tab until canceled. Trigger exposes confirmed Activate and Deactivate actions and records the status and timestamp. **Writes:** add/update `campaignRuns[]` including `campaignId`, `programId`, run status, scheduled/run/completed or canceled timestamps, processed person IDs and counts, and `stepResults[]`; update `smartCampaigns[]` status and update metadata; immediate runs also apply the defined `listMembers[]`/`programMembers[]` mutations and update affected static lists. Append `activityLog[]` for each committed lifecycle action. Activation and future scheduling write configuration only. Never dispatch messages or start workers, timers or background state writes.
