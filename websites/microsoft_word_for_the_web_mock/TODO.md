## P1 — Required workflows

- [x] **P1-01 · Documents — find and organize.** Show Create blank document and a few template choices above Jump back in. Library filters include Recent, Favorites and Shared with me, with text search by title or owner, sortable Name and Last modified columns, and sensible empty/no-results states. Rows show document icon, title, owner or location, modified time, favorite toggle and a more-actions menu. Opening via a library row upserts `documentActivity` for the actor and document with `openedAt` and update metadata. Favoriting/unfavoriting upserts the same relation with `isFavorite` and update metadata. Searching, sorting, changing filters and direct route hydration make zero writes. Shared with me derives from active direct grants to the actor on documents owned by someone else. See [Documents and document activity](assets/data_model.md#documents-and-document-activity).
- [x] **P1-02 · Documents — create, open, rename, copy and delete.** The blank CTA creates and focuses a new editable document named `Document` (suffix on collision). Template cards create independent editable copies. Click the editor title or select File → Rename, trim the name and commit with Enter/blur, cancel with Escape, and validate blank names. Editors and owners can rename and create a copy from File or the row menu. Owners can also delete after confirmation. Create/copy appends `documents` with owner/actor, title, origin IDs, active status, accepted body and tracking off, plus a `documentActivity` entry. A copy starts with its own IDs and the source’s accepted body. Rename updates `documents[].title` and update metadata. Delete sets `documents[].status`, `deletedAt`, `deletedByUserId` and update metadata. Related comments, revisions and access remain inspectable by their IDs, and deleted documents disappear from active views. See [Documents and document activity](assets/data_model.md#documents-and-document-activity).
- [x] **P1-03 · Documents — write and format.** Use a browser editor with a JSON representation of paragraph blocks and inline runs. Support typing, multiline paste, deleting or replacing a range, heading/normal styles, list toggles, alignment, bold/italic/underline, inline find, and selection-preserving toolbar commands. Show saved feedback after document edits and derive the word count from the displayed text. With tracking off in Editing mode, a committed edit updates `documents[].body`, increments `revision`, and stamps `updatedAt` and `updatedByUserId`. Remap relevant `commentThreads[].anchor` and pending `trackedChanges[].range` only when the accepted text positions change. With tracking on or in Reviewing mode, route edits through P1-05. Offer Editing, Reviewing and Viewing in the mode menu. Owners and editors can select all three and default to Editing. Review access defaults to Reviewing and can switch to Viewing. View access stays in Viewing. Mode selection is ephemeral. See [Editor body, ranges and patches](assets/data_model.md#editor-body-ranges-and-patches).
- [x] **P1-04 · Comments — post, reply, edit, resolve, reopen and delete.** Select text or place the caret, then use New Comment in Review, in the Comments panel, or on the selection context menu. Show an anchored draft, Post (also Ctrl/Cmd+Enter), and Cancel. A post creates a `commentThreads` record with `documentId`, `anchor`, `status: "active"` and its first `messages` entry. Replies append a message with its own ID, author, timestamp, `body` and `mentionUserIds`. Typing `@` offers seeded users who can access the document. Authors may edit or delete their own messages. Edit writes message `body`, `mentionUserIds` and edit metadata. Delete writes message deletion metadata, or stamps both thread and initial-message deletion metadata and sets thread `status: "deleted"` when the starter is deleted. Resolving/reopening writes thread `status`, `resolvedAt`, `resolvedByUserId` and update metadata. Open the contextual view for active threads and the list view for active and resolved threads. Selecting a thread scrolls/highlights the anchor when attached. Drafts, selection and filtering stay local. See [Comment threads](assets/data_model.md#comment-threads).
- [x] **P1-05 · Track Changes — capture suggestions.** In Review, offer Track Changes with Off, Just Mine and For Everyone. Persist the choice in `documents[].tracking` with actor and timestamps, plus document update metadata. An edit under tracking or Reviewing mode creates a `trackedChanges` record with document/author IDs, `kind`, `range`, `before`, `after`, `status: "pending"` and timestamps. Updating the actor’s pending insertion or replacement updates its proposed fragment and update metadata. Returning the proposal to the original fragment sets `status: "withdrawn"` and writes decision and update metadata. Preserve the accepted `documents[].body` and `revision` while suggestions are pending. Turning tracking off retains pending changes. Simple Markup uses a margin marker and suggested text projection, and All Markup displays additions and removals inline. Markup toggles and Previous/Next are view actions. See [Editor body, ranges and patches](assets/data_model.md#editor-body-ranges-and-patches) and [Tracked changes](assets/data_model.md#tracked-changes).
- [x] **P1-06 · Track Changes — accept and reject.** Editing access can choose Accept/Reject on a focused change card, use the Review toolbar to step in document order, or accept/reject all pending changes. A decision writes each `trackedChanges` record’s `status`, `decidedByUserId`, `decidedAt` and update metadata. Accept applies `after` to `documents[].body`, increments `revision` once per committed action, remaps affected ranges and comment anchors, and stamps document update metadata. Reject retains accepted content and stamps document update metadata. A bulk decision is one store action and keeps each decided record. Disable decision controls when the actor has review/view access or there are zero pending changes. See [Tracked changes](assets/data_model.md#tracked-changes).
- [x] **P1-07 · Sharing — invite people.** For owners and editors, Share opens a panel with recipient chips, permission selector, optional message, and Send. Offer Can edit, Can review, Can view, and Can’t download. Autocomplete seeded names/emails, normalize typed email addresses, deduplicate recipients, and validate before commit. Send appends one `shareInvitations` record with recipients, permission, message, `status: "sent"`, document ID, actor and timestamp. For each recipient, upsert an active `shareGrants` row with matching permission, recipient identity, `invitationId` and update metadata. Display a local confirmation. See [Invitations and direct grants](assets/data_model.md#invitations-and-direct-grants).
- [x] **P1-08 · Sharing — create, copy and open a link.** Link settings supports Anyone, People in the organization, People with existing access, and People you choose. Provide a permission selector where the scope grants access and recipient chips where scope requires them. Apply updates the dialog draft. Copy link creates or reuses a matching active `shareLinks` record and stamps copy metadata, then offers the selectable URL as a clipboard fallback. The same-session URL opens `/share/:linkId?sid=…` and checks scope, current user, document status and the current access record. The existing-access scope uses the actor’s current direct access. Opening a permitted link leads to Viewing, Reviewing, or Editing and is read-only at the state layer. Copy writes only the link record. See [Sharing links and access](assets/data_model.md#sharing-links-and-access).
- [x] **P1-09 · Sharing — manage access.** From Share → Manage access, list the owner, active People grants and active Links with their permission and scope. Owner can downgrade/upgrade an individual grant or confirm removal of a person/link. Grant edits update `shareGrants[].permission` and update metadata. Removal sets the selected `shareGrants` or `shareLinks` row to `status: "revoked"` and writes `revokedAt`, `revokedByUserId` and update metadata. A link route reflects revocation after reload. Owners keep control of their documents. See [Sharing links and access](assets/data_model.md#sharing-links-and-access).
