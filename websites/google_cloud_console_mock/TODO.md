## P0 — Core shell and Harbor

- [x] **Scaffold and build.** Use React, React Router, and Vite. Set the dev server to port 5484 with strict port checking. Import the unchanged `stateApi(createInitialData)` plugin from `../../templates/state-api.js` in `vite.config.js`. Commit-ready deliverables include the npm lockfile and a passing `npm run build`. Use bundled CSS, system fonts, and original local graphics. Render “Google Cloud Console” as text in the shell and document title.
- [x] **Shell, routes, and project context.** Build the dark product rail and light workspace in [DESIGN.md](DESIGN.md). Support Overview `/`, IAM `/iam`, VM instances `/compute/instances`, VM detail `/compute/instances/:vmId`, Buckets `/storage/buckets`, bucket detail `/storage/buckets/:bucketId`, Billing overview `/billing`, Reports `/billing/reports`, and Budgets & alerts `/billing/budgets`. Project selection updates the `project` query parameter, and billing account selection updates `account`. Keep `sid` in every SPA navigation and use `withSid()` for links outside the router. Derive an omitted scope from the record on a direct detail link, or from the first available project/account for a list. Give unknown records a useful return link. These navigation actions write no business state.
- [x] **State and verifier endpoints.** Copy `templates/dataManager.js` unchanged to `src/utils/dataManager.js`. Await `loadState('google_cloud_console_mock', createInitialData)` behind a neutral loading view before mounting the provider-backed routes. Initialize once per page boot. Each successful business mutation composes one whole-state transaction and invokes `saveState` once in the shared store. Keep reads, filters, cancellation, validation failures, and idle time free of mutation posts. Serve `/state`, `/post`, and `/go` through the template/runtime API. `GET /go` returns `initial_state`, `current_state`, and `state_diff`.
- [x] **Injected worlds.** Use null-safe selectors and stable IDs with server-injected arrays of size zero, one, or hundreds and records missing optional fields. Render explicit empty and no-results states. Keep seeds untouched when a task replaces an array. Use readable fallbacks for missing references and require an available project or billing account for writes that need one. All routes, including direct links and reloads, must sit inside the state and feedback providers. Relative date labels use `new Date()`.
- [x] **Overview and shared interactions.** Show the selected project name and ID, four linked summary panels for IAM principals, VM status, buckets, and billed usage, followed by recent activity scoped by project. Derive all metrics and timeline entries from state. Provide accessible labels, keyboard-operable menus, focus restoration on dialog dismissal, visible loading/empty states, inline validation, and success feedback. Use search, relevant filters, sortable columns, and pagination on the four primary lists. Search/filter intersections drive the result count and changing filters returns to page one. These interactions write no business state.
- [x] **Verifier documentation.** Write root `SCHEMA.md` with every state key, field type, and an Observable State Changes table mapping every implemented user mutation to exact fields, event kinds, references, and lifecycle status. Use the planned schema in [assets/data_model.md](assets/data_model.md) and reconcile the final schema with the implementation.

## P1 — Primary workflows

- [x] **IAM · Browse and grant access.** Show one IAM row per principal, with principal identifier/type, role chips, and inheritance indicated per role. Search by email or role and filter by principal type. “Grant access” opens a project-scoped form with principal type, email, and a searchable role picker. Support granting additional roles to an existing principal. Reject duplicate active project/principal/role tuples and show validation inline. Writes one `iamBindings` row per granted role with `status: 'active'`, `projectId`, `principalType`, `principal`, `roleId`, `source: 'direct'`, `createdAt`, and `actorId`. Append one `activity` entry of kind `iam.grant` per binding.
- [x] **IAM · Edit and revoke roles.** A principal row opens an edit panel with direct role additions and removals. Show inherited roles as read-only. Save changes in one transaction without rewriting untouched grants. Added roles follow the grant write above. Removed roles update the existing `iamBindings` row to `status: 'revoked'` with `updatedAt` and `updatedBy` and append `activity` of kind `iam.revoke`. A single-role revocation names the principal and role in a confirmation dialog. A replacement records a revoke and grant together.
- [x] **VMs · Browse and create an instance.** Show name, status, zone, machine type, internal/external IPs, and row actions. Search names and filter by status and zone. “Create instance” collects name, region/zone, machine type, boot image, boot disk size, and optional external IP. Offer coherent region/zone combinations. Require a valid lowercase name, a positive whole disk size, and uniqueness within active instances in the project and zone. Create a `vmInstances` row with selected configuration, assigned synthetic IPs, project and actor IDs, `status: 'RUNNING'`, and `createdAt`. Append `activity` of kind `vm.create`.
- [x] **VMs · Manage instance lifecycle.** Show configuration and status on the detail page and make actions available there and in the row menu. Running instances can stop or reset. Stopped instances can start. Either can be deleted. Display “Stopped” for underlying `TERMINATED` status. Confirm stop, reset, and delete with the resource name and the action effect. Update `vmInstances.status` to `TERMINATED`, `RUNNING`, or `DELETED` as appropriate. Reset records `lastResetAt` while staying `RUNNING`. All actions set `updatedAt` and `updatedBy` and append `activity` of kind `vm.stop`, `vm.start`, `vm.reset`, or `vm.delete`. A deleted resource leaves the active table.
- [x] **Buckets · Browse and create.** Show name, location, storage class, access mode, and object count. Search names and filter class and location. “Create bucket” collects name, location type and location, storage class, access control mode, and public access prevention. Default to Standard, Uniform, and prevention enabled. Validate a 3–63 character lowercase bucket name with letters, digits, and hyphens, beginning and ending alphanumerically. Enforce unique active names across projects in the synthetic world. Write a `buckets` row with selected configuration, project and actor IDs, `status: 'active'`, and `createdAt`. Append `activity` of kind `bucket.create`.
- [x] **Buckets · Inspect and manage a bucket.** Expose Objects and Configuration tabs. List object names, sizes, and types with prefix search. “Upload files” accepts local files and creates metadata only. Reject duplicate active paths within the bucket before writing. Add `storageObjects` rows with bucket ID, object name, size, MIME type, `status: 'active'`, `actorId`, and `createdAt` and append `activity` of kind `object.upload` per object. After confirmation, Delete object sets `status: 'deleted'`, `updatedAt`, and `updatedBy` and appends `object.delete` activity. Configuration edits save `storageClass` with `updatedAt`/`updatedBy` and `bucket.update` activity. Require an empty bucket for Delete bucket, ask the user to type its name, then set `buckets.status: 'deleted'`, `updatedAt`, and `updatedBy` and append `bucket.delete` activity.
- [x] **Billing · Accounts and reports.** Show the billing account, linked projects, month-to-date cost and grouped service totals. Reports has a date range, project and service filters, and a chart with an accessible values table. Derive both from matching `billingCosts` rows and retain historical attribution using the cost record's `billingAccountId`. Read-only views and controls write no business records.
- [x] **Billing · Budgets and alerts.** Show searchable budgets with their scope, target, spend, and threshold progress. Create and edit a named monthly budget with an all-project or selected-project scope, a positive currency amount, and one or more distinct percentage thresholds using Actual or Forecasted spend. Validate names and amounts, and retain entered values on validation failure. Save `budgets` rows with `billingAccountId`, `projectIds`, amount, currency, thresholds, and creation or update metadata. Delete after named confirmation by setting `status: 'deleted'` with update metadata. Append `budget.create`, `budget.update`, or `budget.delete` activity.
- [x] **Billing · Manage project billing.** Show current links on Billing overview and provide “Change billing account”, “Enable billing”, or “Disable billing” as applicable. Confirm the selected project/account change, then update `projects.billingAccountId` to the destination account ID or `null`, plus `updatedAt` and `updatedBy`. Append `project.billing_change` activity with the previous and resulting account IDs. Keep historical usage unchanged.
- [x] **Workflow verification.** On localhost port 5484, use the installed Node Playwright and Chromium to exercise IAM grant/edit/revoke, VM create/stop/start/reset/delete, bucket create/upload/configuration change/object and bucket deletion, and billing reporting/budget create/edit/delete/project relink. Check each write via `/go?sid=...`, reload representative detail routes, verify cancel and invalid submissions leave state unchanged, exercise empty/injected worlds, check session isolation and zero idle writes, and record results plus observed fields in `TEST.md`. Keep scratch files out of tracked paths. The parent runner handles Docker certification and commits.

## Scope limits

The session opens with a synthetic signed-in user. Account registration, authentication, real cloud calls, SSH, payment methods, actual file storage, physical provisioning, and email delivery are outside the implementation scope.
