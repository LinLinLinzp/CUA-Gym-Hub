# Freshdesk proposed state schema

Implement `createInitialData()` as a pure function returning a fresh object with the keys below. These names form the verifier-facing proposal for `SCHEMA.md`. Use strings for IDs, ISO 8601 UTC strings for timestamps, integers for minute durations and policy ranks, booleans for flags, and `null` for absent relationships or deadlines. New records get unique IDs and timestamps from `new Date().toISOString()`. All examples are synthetic.

## Relationships and derivation

- Join records by ID and use `tickets.number` for display and numeric search. Assign the next available ticket number above the current numeric maximum, with a fallback starting number of 1001. If an injected required relationship is unavailable, show a neutral label and keep the original ID. Render absent optional fields and arrays safely, and preserve injected fields on record updates.
- Filter active, undeleted custom SLA policies by conditions, then take the lowest numeric rank. Use the active default as fallback. Custom policies require at least one condition. If no policy applies or a target is missing, show an unavailable deadline. Calendar targets add elapsed minutes. Business targets accrue minutes only inside schedule windows and advance past evenings and weekends. A missing or invalid schedule leaves the corresponding deadline unavailable.
- On creation or a priority/matching-field edit, derive unfulfilled first response and resolution deadlines from `createdAt`, and a next response from `lastCustomerReplyAt` when it falls after the last public response and a first response already exists. Keep manual overrides and historical completed deadlines. Resolve and close fulfill the active resolution indicator. A transition to closed records `closedAt` and sets `resolvedAt` if needed. Reopening clears both timestamps. A first public agent response sets `firstRespondedAt`. Public agent responses update `lastRespondedAt` and clear the outstanding `nextResponseDueAt`. Private notes can change status when submitted with an explicit status selection.
- A group response is visible to an agent in one of its groups. A personal response is visible to its owner. Admins manage shared responses and their personal responses in the library. The reply picker uses composer visibility for every agent. Match titles and short codes case-insensitively, require a nonempty title and body, validate provided short-code uniqueness among active responses, and retain line breaks. If a known placeholder has no value, use a neutral fallback. Keep unrecognized placeholder text editable in the draft.
- Use the runtime clock to display relative dates and compare unfinished deadlines. Calculations for display leave state untouched. Seed history and timing fields for existing customer replies so the next-response display is exercised without a customer simulator.

## Observable state changes

| User action | State written |
| --- | --- |
| Create ticket | Append a fully populated `tickets` record and a linked `ticketEvents` record. Append `contacts` only for a new requester. |
| Edit properties, transition status, bulk assign or bulk change status | Patch changed properties, lifecycle timestamps, impacted SLA fields and `updatedAt` on each affected `tickets` record. Append one `ticketEvents` entry per affected ticket with its changed fields. |
| Send reply or add note | Append `ticketConversations` with visibility and any template IDs. Patch `tickets.updatedAt`, selected lifecycle fields, and qualifying response timestamps. Append linked `ticketEvents`. |
| Override a ticket deadline | Set the corresponding due and override fields and `updatedAt` on `tickets`. Append `ticketEvents` with due field changes. |
| Create, edit, enable, disable, reorder or delete a policy | Append or patch `slaPolicies` fields, `rank`, `updatedAt` or `deletedAt`, as applicable. Append `adminEvents` for each changed policy. |
| Create or rename folder | Append `cannedResponseFolders` or patch its `name` and `updatedAt`. Append `adminEvents`. |
| Create, edit, move or delete response | Append `cannedResponses` or patch changed fields, `folderId`, `updatedAt` or `deletedAt`, as applicable. Append `adminEvents`. |
| Browse, filter, sort, switch views or insert a template into an unsent draft | Zero writes to business state. |

Use an actor from `account.currentAgentId` for saved changes. If an injected world omits that agent from `agents`, keep the configured account actor ID and render neutral identity text. Return the full state only after performing an explicit successful mutation. Canceled, rejected and unchanged submissions produce zero writes.
