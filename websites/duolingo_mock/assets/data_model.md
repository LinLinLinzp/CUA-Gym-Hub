# Proposed Harbor data model

Implement `createInitialData()` in `src/data/seed.js`. Document the implemented form in `SCHEMA.md`. Records are JSON objects. IDs and enum fields are strings, quantities and targets are numbers, and timestamps are ISO strings. Use `null` for explicit absence. Every record below has an `id` except the singleton `profile`. Each action stamps the account actor and a runtime `new Date().toISOString()` in a new event, attempt, progress, contribution or nudge as applicable. Reuse the same timestamp across records written in one action.

## Courses

Course and lesson definitions are catalog data. One enrollment per course holds the learner's current run and summary. Sort the learner's active course first. Add creates a run of `1` or increments the removed record's run, writes `status`, `xp`, `lessonsCompleted`, `updatedAt` and `removedAt`, sets `profile.activeCourseId`, and appends a course event. A reactivated record keeps its original `id` and `createdAt`. Switch saves only the active course and its event. Remove preserves historical attempts and adds a removal event, updating the enrollment and active pointer in one write. If the removed course was active, use the first still-enrolled, existing course in enrollment order. When the active ID is absent or stale, select a display-only fallback from the remaining enrollments.

### Lesson completion

Use the next lesson by catalog `order` for that course, based on the current run's attempt IDs. If an injected enrollment supplies summary progress without attempt rows, use `lessonsCompleted` as a lower bound for the next index. `Finish lesson` accepts one existing playable lesson for the current enrollment. Score the answer, award the lesson's configured XP, append a completed attempt, and increment `enrollments[].xp` and `lessonsCompleted` and set `updatedAt`. Appending once per enrollment, run and lesson prevents duplicate progress. A canceled or abandoned lesson produces no record. After catalog lessons are exhausted, show course completion.

The same store action appends goal progress for each active goal and one contribution for each active eligible quest with a matching metric. `xp` contributes earned XP, `lessons` contributes `1`, and `perfect_lessons` contributes `1` only for a perfect attempt. Omit zero contributions. Set completed quest state and append its event when the sum meets the target. Preserve all persisted fields unrelated to the action.

## Goals

Create and edit the target, label, cadence and metric. Validate trimmed labels and positive whole numbers before saving. Preserve ID and creation time on edit. Archive sets the archive status and timestamps and preserves prior events and contributions. Group progress by timestamps in a UTC day or a UTC week beginning Monday, relative to runtime `new Date()`. Sum rows with the current metric within the selected period. Editing a cadence regroups existing compatible rows. A completed goal filter shows current-period rows that meet the target, and prior periods can show completion from recorded progress and target history. The stored lifecycle stays active across periods until archive. An archived record remains readable and receives no new progress.

## Friends Quests

An available quest can be joined once with an eligible mutual friend. Use runtime `new Date()` when comparing optional start and end dates and when displaying remaining time. Expiration is a display and action gate. A completed reward remains claimable after the quest period. Render missing friends as `Partner unavailable` and preserve challenge history. Disable nudge when a recipient cannot be resolved. On a valid join set `partnerId`, `status: 'active'` and `joinedAt`, and append the `joined` event. Show each active quest if an injected world contains multiple. Use the participant IDs to group progress. On completion save `status: 'completed'`, `completedAt`, and the `completed` event. Nudge stores the chosen preset and the partner recipient. Claim guards the completed state, sets `status: 'claimed'` and `claimedAt`, increments `profile.gems` by `rewardGems`, and appends `reward_claimed`. All notices and rewards stay within this account's local world.
