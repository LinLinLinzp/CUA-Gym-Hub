# Venmo account UI — implementation plan

**Ready for development · 2026-11-18**

Read [DESIGN.md](DESIGN.md) for the original interface, [assets/README.md](assets/README.md) for product research, and [assets/data_model.md](assets/data_model.md) for the planned state contract.

## P0 — Shell and Harbor runtime

- [x] **P0.1 — Scaffold and build.** Set up Vite, React, React Router and the npm lockfile inside this site. Set the title to Venmo. Configure Vite for localhost port 5331 with strict port handling. Use the shared `stateApi(createInitialData)` from `../../templates/state-api.js` in `vite.config.js` and copy `templates/dataManager.js` unchanged to `src/utils/dataManager.js`. Run `npm run build` and verify the built app with the state middleware. When launching a persistent dev server on Windows, use `Start-Process -WindowStyle Hidden` and pass the absolute Vite entry point.
- [x] **P0.2 — Account shell and routes.** Implement the original horizontal navigation and workspace in DESIGN.md. Routes are `/` (Overview), `/activity`, `/activity/:paymentId`, `/requests`, `/requests/:requestId`, `/splits`, `/splits/:splitId`, and `/statements`. Put all routes and overlays inside the providers they use. Preserve `?sid=` through navigation, links and redirects, using `withSid()` for links leaving the router. Support direct loads and refreshes, with a recovery link for unknown routes and unavailable records.
- [x] **P0.3 — One state write path.** Show neutral loading UI until `loadState('venmo', createInitialData)` resolves. Commit validated mutations through one store action that computes the next state from the latest snapshot and calls `saveState` once with the whole state. Protect confirmation controls against double submissions. Keep drafts, navigation, searches, filters and derived totals transient. Use middleware endpoints `/state`, `/post` and `/go` for session isolation and verifier inspection. Serve all runtime assets locally.
- [x] **P0.4 — Injected worlds.** Respect replacement arrays and merged objects. Render empty, singleton, large and sparsely populated datasets on all routes. Where optional fields or linked records are missing, show the available data and disable only actions requiring the missing data. Use `new Date()` for relative date displays and current timestamps. Seed fixed IDs and dates as specified below.

## P1 — Required workflows

- [x] **P1.1 — Payments.** From Overview or Activity, open **Pay or request** in Pay mode. Search synthetic contacts by name, handle, email or phone, select one, enter a positive USD amount and note, then review recipient, total and funding source. Default to Venmo balance when it covers the full amount, otherwise offer the available linked methods. Confirm once and show the payment detail. **Writes** one completed `payments[]` record with `id`, `type`, `status`, `actorId`, `senderId`, `recipientId`, `amount`, `currency`, `note`, `fundingSourceId`, `createdAt` and `completedAt`. A balance-funded payment also reduces `account.balance` by the exact amount in the same write. Activity supports All/Sent/Received filters, search by counterparty or note, newest first, and a persistent detail route.
- [x] **P1.2 — Requests.** Use Request mode of the same composer and confirm the person, amount and note. The Requests page shows Incoming and Outgoing with status filters and detail links. **Writes** one pending `requests[]` record with `id`, `status`, `actorId`, `requesterId`, `payerId`, `amount`, `currency`, `note` and `createdAt`. For pending incoming requests, offer **Pay** (same funding review; adds a completed `payments[]` record with `requestId`, updates `account.balance` if balance-funded, and writes `requests[].status='paid'`, `paymentId`, `updatedAt`, `updatedById`) or **Decline** (writes `status='declined'`, `updatedAt`, `updatedById`). For pending outgoing requests, offer **Remind** (appends a structured entry to `requests[].reminders`) and **Cancel** (writes `status='cancelled'`, `updatedAt`, `updatedById`). Confirm terminal actions, preserve the original request record and derive its status in both list and detail views.
- [x] **P1.3 — Splits.** Start **Split an expense** from Overview or Splits, or start **Split payment** from a completed outgoing payment detail. Select one or more distinct contacts and include yourself by default with a toggle. Require at least two participants overall. Enter the total (prefilled from the source payment when applicable) and note, and choose Equal or Custom. Display every share and the total to request before confirmation. Allocate equal shares in integer cents in participant order, distributing the remainder one cent at a time. Require custom shares to add to the exact total and each participant's share to be positive. **Writes** one `splits[]` record with `id`, `actorId`, `ownerId`, `amount`, `currency`, `note`, `method`, `sourcePaymentId` when applicable, `status='pending'`, `createdAt` and `shares[]`. Each share records `userId`, `amount` and a `requestId` for each non-owner. In the same write create one pending `requests[]` record per non-owner with matching share amount and `splitId`. Splits list and detail show each linked request's status. Any later terminal update to a child request recomputes `splits[].status` and writes split `updatedAt` and `updatedById` in the same mutation.
- [x] **P1.4 — Statements.** Show Month and Year controls, a preview of posted activity in that UTC calendar month and a **Download CSV** button. Default to the most recent month with posted activity, falling back to the current month and year. Keep period selection transient. List timestamp, payment ID, counterparty, note and signed USD amount, with incoming, outgoing and net totals. Generate a local CSV from the same rows in the same order, with proper CSV escaping and formula-safe text cells. Empty months show an empty preview and can export a header-only CSV. On each download, **write** one `statementExports[]` record with `id`, `actorId`, `createdAt`, `status='generated'`, `periodStart`, `periodEndExclusive`, `format='csv'`, `filename`, `currency`, `transactionIds`, `transactionCount`, `totalIncoming` and `totalOutgoing`.
- [x] **P1.5 — Acceptance and verifier handoff.** Publish `SCHEMA.md` with every top-level key, record shape and an **Observable State Changes** table listing each mutation's exact paths. Exercise payments, requests, splits and statements in installed Node Playwright from `PILOT_PLAYWRIGHT` using Chromium at localhost:5331, and verify each write through `/go?sid=…`. Cover funded payment and request settlement, request decline/remind/cancel, equal rounding and custom splits, split child links, statement period boundaries and actual CSV contents. Also cover invalid inputs, canceled confirmations, direct links, hard refresh, injected data, sid isolation and no idle writes. Record results and observed fields in `TEST.md`. Place runner scratch files under a gitignored site directory or remove them. The parent runner handles Docker dynamic certification and commits.

## P2 — Depth

- [x] **P2.1 — Multi-recipient composer.** Add a list of selected counterparties with an explicit amount per recipient and aggregate review. Write one payment or request per counterparty using the existing shapes in one store mutation. Validate total funding when paying.

## Seed data

- [x] Create deterministic English-language fixtures in `src/data/seed.js`. Start as Avery Morgan with 32 contacts, 72 payments across six months, 48 requests across directions and statuses, and 24 splits with valid request and share references. Include a mix of payment sizes and everyday notes, multiple handles with shared name prefixes, and incoming and outgoing pending requests reserved for manual tests. Include at least one empty statement month and at least one month with mixed inflows and outflows. Seed a balance, a bank and a debit card. Start `statementExports` empty because it represents downloads in the active session.

## Out of scope

Authentication, real account actions, bank linking, receipt scanning, scheduling, email delivery, and social feeds are outside the four seed workflows.
