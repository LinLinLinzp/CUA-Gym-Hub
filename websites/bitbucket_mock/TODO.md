## P1 — Repositories

- [x] **P1-R1 · Find and browse repositories.** Show name, project, visibility, description, latest build and last updated in the workspace directory. Combine name search with project, visibility and Starred filters. Sort by last updated by default, with name order available. Source opens the default branch and shows a branch picker, breadcrumb, directory/file rows and README preview. Commits shows author, message, short hash and time with commit detail. Branches lists name, head and last update. **State writes** none for browsing, sorting or filtering.
- [x] **P1-R2 · Create a repository.** From Create or the directory, open a repository form with workspace, existing project, name, privacy (Private by default), description and Include a README? (Yes or No). Show the computed lowercase URL slug and validate a nonempty name, maximum 62 characters, and slug uniqueness among active repositories in the workspace. On success open Source. **State writes** append `repositories[]` with workspace/project, creator, name, slug, visibility, description, timestamps and `defaultBranchId`. Append a `branches[]` record for `main`. With README, append `commits[]` with `README.md` in `changes[]` and set `main.headCommitId`. Without README, `main.headCommitId = null` and Source offers Add file.
- [x] **P1-R3 · Update, star and delete a repository.** Repository settings saves display name, description, project, visibility and default branch. Keep the original slug as the route key on rename. Star/unstar from the repository banner and surface active entries in Starred. Confirm deletion from Manage repository, then return to the directory. Hide deleted repositories and their scoped records from workspace lists and search. **State writes** settings updates the selected `repositories[]` fields, `updatedAt` and `updatedBy`. Star/unstar creates or updates `repositoryStars[]` keyed by repository and user, with `starredAt` and nullable `removedAt`. Delete sets `repositories[].deletedAt/deletedBy` and updates its modification fields. Related records retain their IDs for verification.
- [x] **P1-R4 · Create a branch and commit a file.** Branch creation takes a source branch and a unique valid name, supports names with slashes, and seeds the new head from the source head. Source supports Add file and Edit for text files. Require a normalized repository-relative path and commit message. Reject duplicates on add, missing files on edit and edits from an out-of-date head. Display the resulting commit and allow switching branches to compare the file state. **State writes** branch creation appends `branches[]` with `sourceBranchId`, `headCommitId` and actor/timestamps, and touches the repository. Commit appends `commits[]` with `parentIds` and a structured path/content change, advances `branches[].headCommitId/updatedAt/updatedBy`, and touches the repository.

## P1 — Pull requests

- [x] **P1-PR1 · Find pull requests and open review.** Workspace list searches by title or PR number and filters by project/repository, status, Mine and Reviewing. Repository list scopes to one repository. Default both to Open, newest updated first. Rows show author, title, number, status, branches, reviewers and activity. Detail has Overview, Files changed and Commits. Overview shows description, participants, merge checks and activity. Files changed shows a path list, line numbers and add/remove markers. Commits lists source-side changes. **State writes** none for browsing, filtering, tab changes or diff expansion.
- [x] **P1-PR2 · Create and edit a pull request.** Launch from Create, the repository PR list or a nondefault branch. Pick two distinct branches in the same repository with at least one source-side commit/included change. Default the destination to the repository default branch. Prefill title from the latest source commit and allow editing, a description, multiple reviewers and a close-source-on-merge choice. Preview changes and commits. Prevent a duplicate open PR for the same source/destination pair. In an open PR, allow its author to update title, description, reviewers and close-source choice. **State writes** create appends `pullRequests[]` with a repository-local number, branch/head IDs, author, title, description, reviewer IDs, close-source choice, `status = open` and actor/timestamps. Edit updates the named fields and modification fields. Each successful save appends `pullRequestActivity[]` with the action and changed fields.
- [x] **P1-PR3 · Comment, assign tasks and review.** Submit PR-wide or inline comments, reply within the thread, and resolve/reopen threads. Inline anchors hold the file path, source/destination side, line number and commit ID. Add a task on Overview or from a comment, optionally assign it to the author or a reviewer, and complete/reopen it. The signed-in reviewer can Approve, Request changes or clear their review on an open PR created by another user. Reflect these actions in Activity and in the reviewer summary. **State writes** posting a comment or reply appends `pullRequestComments[]`. Resolving or reopening a thread updates the root's status and actor/timestamps. Task creation appends `pullRequestTasks[]`. Completing or reopening it updates its status and actor/timestamps. Review upserts `pullRequestReviews[]` by PR and user. Each action appends `pullRequestActivity[]` and updates `pullRequests[].updatedAt/updatedBy`.
- [x] **P1-PR4 · Merge or decline.** Merge displays configured approval/task checks, branch comparisons and a confirmation with Merge commit or Squash and an optional Close source branch checkbox. Revalidate both heads and checks at submit. Show any files with conflicting changes. Decline confirms, optionally records a reason, and takes the PR out of Open. A fresh PR can later be created from the same branches. **State writes** merge appends `commits[]` with the result and parent IDs, advances the destination `branches[]` head and touches the repository. If opted in and permitted, set and stamp the source branch's `closedAt/closedBy`. Merge sets the PR's `status = merged`, captured pre-merge heads, `mergedAt/mergedBy`, `mergeCommitId`, `mergeStrategy`, `sourceBranchClosed` and modification fields. Decline sets `status = declined`, captured heads, `declinedAt/declinedBy/declineReason` and modification fields. Both append `pullRequestActivity[]`.

## P1 — Pipelines

- [x] **P1-C1 · Inspect pipeline history and logs.** Show newest builds first, with pipeline name and number, status, branch, commit, trigger, actor, start time and duration. Combine branch, pipeline type, status and trigger filters. A build number opens results with a summary, step list, step status, expandable log sections and attempt selection. Distinguish loading, no results, not configured and missing logs. **State writes** none for filtering, opening logs or choosing a step/attempt.
- [x] **P1-C2 · Configure and enable Pipelines.** In a repository without definitions, offer a starter Build and test template from Pipelines. Show the contents of `bitbucket-pipelines.yml` and a confirmation. Reserve that file for pipeline setup and display it read-only in Source. On an existing configuration expose Enable/Disable in repository settings. Existing run details remain readable while disabled. **State writes** starter setup appends `pipelineDefinitions[]` and a config-file `commits[]` record on the default branch, advances `branches[].headCommitId/updatedAt/updatedBy` and sets `repositories[].pipelinesEnabled`, `pipelineConfiguredAt/By`, `pipelineSettingsUpdatedAt/By` and modification fields. Enable/disable sets `pipelinesEnabled`, `pipelineSettingsUpdatedAt/By` and modification fields.
- [x] **P1-C3 · Run a pipeline.** Open Run pipeline from history, a branch row or commit detail. Prefill the branch or commit for contextual entry points, select an available default/branch/custom definition and collect its declared non-secret variables. Validate definition eligibility, enabled state, commit and required inputs. Reveal the new result immediately. **State writes** append `pipelineRuns[]` with the next repository-local build number, definition and target snapshots, `trigger = manual`, input values, actor, timestamps, status, duration, and structured steps and attempts with seeded output. A run uses its fixture outcome at submission. Keep active fixtures static until stopped by the user.
- [x] **P1-C4 · Stop and rerun.** Confirm Stop on an active run. On a failed run offer Rerun failed steps and Rerun entire pipeline. A failed-step retry keeps the build number and exposes original and retried logs. A whole rerun opens a new build for the original commit, definition and inputs. **State writes** Stop sets `pipelineRuns[].status = stopped`, `stoppedAt/stoppedBy`, finish/duration fields and latest active step attempt status. Failed-step rerun appends `pipelineRuns[].retries[]` and affected `steps[].attempts[]`, then updates run status, finish/duration and modification fields. Whole rerun appends a fresh `pipelineRuns[]` record with `trigger = rerun` and `rerunOfRunId`.
