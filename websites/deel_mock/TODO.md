## P1 — Contracts, invoices and time off

- [x] **Contracts / find and review.** Search by name, title or contract number. Filter by status and contract type and sort by start date. Detail shows scope, contract dates, worker and billing entity, rate or milestone schedule, signature status and linked invoices. List and detail views write no records.
- [x] **Contracts / create, edit and send for signature.** Use a worker/agreement step, payment terms step and review step. Select an existing contractor or enter a new name and email while creating an agreement. Include Fixed rate, Pay as you go and Milestone, with type-specific terms, start and optional end dates, scope, currency and legal entity. `Save draft` creates or updates `contracts[]` and appends `activity[]` (`contract.created` or `contract.updated`). `Sign and send` records `clientSignedAt`, `sentAt`, `updatedAt`, `status: pending_signature` and `activity[]` (`contract.sent`). A direct send creates the contract with its final status. Either action appends a `workers[]` record in the same save if the agreement introduces a contractor. Only Draft can be edited or sent. `Cancel contract` on a pending signature requires confirmation and writes `status: cancelled`, `cancelledAt`, `updatedAt` and `activity[]` (`contract.cancelled`). Seed signed Active agreements. The local send stores the signature and invitation state.
- [x] **Invoices / find and inspect.** Search invoice number or contractor, filter by status and currency and sort by due date. Detail shows issue/due dates, line items, amounts, total, billing entity, payment history and linked contract. `Download invoice` produces a local CSV containing the displayed invoice and line items. Read and download actions write no records.
- [x] **Invoices / release payment.** Select one payable invoice or select multiple Open or Overdue invoices in a single currency. Show the selected count and total, render a review with line items, total and synthetic payment method, then confirm. Set each invoice to `processing`, write `paymentId` and `updatedAt`, append one linked `payments[]` record with amount/currency/method and `activity[]` (`payment.released`) in the same save. Persist payee allocations and prevent a repeated confirmation from paying the same invoice twice. Clearing selection and cancelling the review leave state unchanged. Historical Paid rows come from seed or injection.
- [x] **Time off / request, amend and withdraw.** Show Requests, Balances and a Team calendar or upcoming list, with search by worker and filters for type and status. `Request time off` selects an employee and leave type, takes start/end and a note, and displays the calculated quantity. Validate date order and overlapping pending/approved requests for that employee. Allow a half day on a single weekday. `Submit request` appends `timeOffRequests[]` and `activity[]` (`time_off.requested`). Editing Pending requests updates the inputs and `updatedAt` and adds `time_off.edited`. Confirming withdrawal sets `status: cancelled`, `cancelledAt`, `updatedAt` and adds `time_off.cancelled`. Derive balances from approved requests and the seeded allowance.
- [x] **Time off / approve or deny.** Surface pending team requests in the overview queue as well as the Time off list. Show worker, type, requested days, balance and note in the detail view. Confirm `Approve` or `Deny`, allow a denial reason, and set `status`, `reviewedBy`, `reviewedAt`, `decisionNote` and `updatedAt` on `timeOffRequests[]`. Append `time_off.approved` or `time_off.denied` to `activity[]`. Keep completed decisions discoverable in the status filter and disallow a second decision on the same request.
- [x] **Verifier handoff.** Write `SCHEMA.md` against the final implementation with all top-level keys and an Observable State Changes table. Exercise each P1 mutation on port 5396 in the installed Chromium via Node Playwright from `$env:PILOT_PLAYWRIGHT`, with isolated session IDs, reloads, and same-session `/go` assertions. Cover clean default state, empty and sparse injected data, large lists and idle write counts. Save test scratch under an ignored path or remove it. Record workflow steps and exact persisted fields in `TEST.md`, then leave Docker certification and commits to the parent runner.

## Scope of the local account

Use synthetic records, existing signed-in access, local signing and local payments. The simulated workspace starts at organization operations. Account creation, password or identity flows, external invitations, money movement, payroll and banking integrations are outside this scope.
