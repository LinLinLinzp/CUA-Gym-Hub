## P1 — Required workflows

- [x] **P1.1 — Courses.** Search My courses by full or short name. Filter by category, dates (current, future, past) or starred, sort by title or start date, and paginate. Course detail shows code, name, summary, schedule, visibility and sections with activity links. Creating a course requires full name, unique trimmed case-insensitive short name, category and start date. End date is optional and must be on or after start. Create `courses[]`, a default `courseSections[]` item named General, and the instructor's active teacher `enrolments[]` row atomically. Course Settings changes the same course's name, code, category, summary, dates and visibility while preserving IDs and relations. Star and unstar upsert the instructor's `coursePreferences[]` row. In Participants, search by name or email, then use **Enrol users** to select available students and save active `enrolments[]` rows. A row action suspends or restores enrolment in place and retains history. The submissions roster and gradebook reflect active student enrolments.
- [x] **P1.2 — Assignments.** Search and filter Assignments by title, course and visibility, with a due date sort. From a course section, **Add assignment** opens a labelled form with title, instructions, section, open and due date/time, maximum points and visibility. Require title, positive numeric max points, and due date at or after open date when both are set. Create `assignments[]` and its linked `gradeItems[]` record atomically. Settings edits the same assignment and updates the grade item's name, maximum and visibility where changed. Block reducing the maximum below any stored score or override. Provide a course roster in **Submissions**, filterable by student or submission state. From a student row, **Open learner workspace** links into the course-scoped synthetic learner view. The learner can save nonempty online text as a draft and submit it for grading. These actions create or update one `submissions[]` record for the assignment and learner. Enforce active enrolment, visible course and assignment, and open date on learner access and write. Allow late submission and record it at submission time. Submitted work is read-only in learner view. Instructor opens **Grade** on a submitted row to review the text, enter numeric points and feedback, and save. Upsert the activity `grades[]` record and link it to the submission. Reflect the score in Gradebook and the feedback in the learner view.
- [x] **P1.3 — Gradebook.** Gradebook landing lists courses and points to their grader reports. Grader report shows active students as rows and course grade items as columns, with student search, item filter, paging, sticky name column and course totals calculated from effective scores. From **Gradebook setup**, create a manual item with title, positive maximum points and visibility. Save a `gradeItems[]` record with a null assignment link. **Edit grade** on an assignment cell sets a manual override with numeric points and optional feedback, leaving the activity score and submission intact. **Remove override** restores the activity score or an ungraded cell. For manual items, **Edit grade** enters the base score and feedback. These operations upsert `grades[]` by item and student. Treat zero as a score and blank as ungraded. Validate the item maximum and show the override indicator and effective value in both grading entry points.
- [x] **P1.4 — Schema and acceptance handoff.** Document the implemented JSON shape and exact writes in `SCHEMA.md`, including the Observable State Changes table. Exercise each workflow through the UI and record evidence in `TEST.md` with the affected keys and fields from `/go`. Use local Chromium via the installed Node Playwright package pointed to by `PILOT_PLAYWRIGHT`. Start a persistent server with PowerShell `Start-Process -WindowStyle Hidden`, the target directory as working directory, and an absolute Vite entry point. Place test scratch files in an ignored location under the target directory or remove them afterward. Use fresh SIDs for baseline, persistence, session isolation, and injected worlds. Include direct hard reload, zero/invalid scores, empty/missing optional records, a large roster, idle POST counting, and a browser request check for offline assets. Leave Docker certification and commits to the parent runner.

## Scope

The account starts as a course-managing instructor. The course-scoped learner workspace supports online text submissions with synthetic enrolled learners. Authentication, institutional integrations, real uploads, real messaging, and additional activity types are outside this phase.
