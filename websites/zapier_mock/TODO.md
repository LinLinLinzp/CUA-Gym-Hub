## P0 — Shell and Harbor runtime

- [x] **Workspace and routes.** Open `/` on the Zaps inventory. Provide persistent navigation to Zaps, Zap history, and App connections, with a visible workspace name and signed-in user. Support `/zaps`, `/zaps/:zapId`, `/history`, `/history/runs/:runId`, and `/connections`. Preserve `sid` on every navigation, including deep links from runs and connection dependencies. Use `withSid()` for internal links outside the router. Keep every route inside its providers. Missing or deleted records render a useful empty view with a working back link. Navigation writes no records.
- [x] **State and evaluator API.** Copy `templates/dataManager.js` unchanged to `src/utils/dataManager.js`. Import `stateApi` from `../../templates/state-api.js` in `vite.config.js` and pass the same `createInitialData` used by the client. Gate rendering behind `await loadState('zapier_mock', createInitialData)` and use a central user-action dispatcher to call `saveState` once per successful mutation with the entire updated state. Serve `/state`, `/post`, and `/go` through the plugin in dev and preview. No mount, filter, navigation, or timer-driven business-state writes. Test fresh `sid` isolation and injected replacement arrays, partial records, extra keys, and large inventories. Preserve injected keys and use fallbacks in views when references or optional data are missing.
- [x] **Offline build.** Configure Vite port `5506` with `strictPort`. Use the title `Zapier`, text branding, local styles, and original local visuals. Build with `npm run build`, retain `package-lock.json`, and keep runtime requests local to the state API. For a persistent Windows dev server, use `Start-Process -WindowStyle Hidden` with the absolute Vite JavaScript entry point, the site as the working directory, and port `5506`. Test only on localhost using Chromium and the Playwright installation from `PILOT_PLAYWRIGHT`. Keep scratch files gitignored or remove them when finished.

## P1 — Zaps

- [x] **Find and manage Zaps.** Show name, ordered app labels, folder, owner, On/Off/Draft state, and last updated time in a searchable table. Combine case-insensitive title/app search with status and folder filters and sort by name or recently updated. Paginate after filtering and sorting. Open the editor from a row. A row menu supports Rename, Duplicate, Move to folder, and confirmed Delete. Rename and move update `zaps[].name` or `.folderId` and update metadata. Duplicate inserts a new draft with fresh Zap and step IDs and cleared test/publication metadata. Delete removes the Zap and retains historical `runs` snapshots. Search, filtering, sorting, and viewing write no records.
- [x] **Create and edit a Zap.** `Create Zap` inserts a draft in `zaps` with one empty trigger and opens `/zaps/:zapId`. Edit the name and configure the trigger and one or more actions through an ordered step list and detail form. Choose app, app-specific event, matching connection when required, and relevant configuration values. Let actions accept literal values or mappings from earlier steps. `Save draft` persists `zaps[].name`, the ordered `draftSteps`, `updatedAt`, and `updatedBy`. Support add/remove action with dependency validation. An existing published version continues to use `publishedSteps` while draft edits are saved. Closing an unsaved form writes no records.
- [x] **Test, publish, and switch on or off.** Test a configured step against a deterministic synthetic sample, show the input and output, and persist the tested draft and its `draftSteps[].lastTest`. Validate required fields, mappings, and enabled connections before publishing. Publish copies `draftSteps` to `publishedSteps`, increments `version`, writes `publishedAt`, and sets `enabled=true` and `status='on'`. On/Off toggles update the published Zap's `enabled`, `status`, and edit metadata without changing `publishedSteps`. A draft with no published version uses Publish as its activation control. Tests create no history runs or billable tasks.

## P1 — Task history

- [x] **Investigate runs and task usage.** Use `Zap history` in navigation with `Zap runs` and `Task usage` tabs. Show timestamp, Zap name, status, tasks used, and app labels on each run. Search by Zap name or run ID and filter by status, Zap, and date range, with an all-time initial range. Show a detail route with run status, linked replay source where present, and selectable step inputs, outputs, and errors. Task usage aggregates `runs[].taskCount` by Zap and day in the selected range, including runs whose Zap was deleted. These views write no records.
- [x] **Replay a run.** Offer a confirmed `Replay` on errored runs with a published, enabled Zap and an unchanged trigger app/event. If a required connection is missing or expired, show the required repair without writing state. On success, append a new `runs` record with a fresh ID, the original in `replayOfRunId`, `source='replay'`, the current version, copied trigger input, fresh step results, actor, timestamp, and numeric task count. Keep the original run intact and open the new run detail. A successful replay should be visible in task usage.

## P1 — Connections

- [x] **Find and add connections.** Search by connection label, account label, or app. Filter by app and status. Show label, app, status, owner, last modified, and derived linked Zap count. Expose linked Zap names from each row. `Add connection` uses a local app picker and synthetic account label plus optional display name, then inserts `connections[]` with app, owner, status `active`, and creation/edit metadata. Make the new connection available in the matching app's step editor. Search, filtering, and viewing dependencies write no records.
- [x] **Maintain connections.** Row actions support Rename, Test connection, Reconnect, and confirmed Delete. Rename updates `connections[].name`; Test writes `lastTestedAt` and `lastTestResult`; Reconnect sets `status='active'` and `lastReconnectedAt` on the same ID; each updates edit metadata. Delete lists dependent Zaps, removes the connection, and sets `enabled=false` and `status='off'` with edit metadata on affected enabled published Zaps in the same state write. Saved draft and published steps retain the removed ID and show a replace-connection prompt. Never request credentials or transmit data to an integration.

## P2 — Depth
