# Supabase implementation plan

> **Status** IMPLEMENTED AND VERIFIED  
> **Planning date** 2026-11-18

Read [SEED.md](SEED.md), the [Harbor contract](../../HARBOR_CONTRACT.md), [DESIGN.md](DESIGN.md), and the [state model](assets/data_model.md) before implementation. The operator opens a preselected synthetic project called Trailhead.

## P0 — Shell and Harbor runtime

- [x] **Local project shell.** Use React and Vite in this directory, with a lockfile, a production build, and a strict dev port of 5486. Use Supabase as a text wordmark and page title. Build the original shell in DESIGN.md. Give the project overview four entry points with state-derived counts and a clear route back to the overview.
- [x] **Navigation.** Support `/`, `/tables`, `/tables/:tableId`, `/auth/users`, `/storage`, `/storage/:bucketId`, and `/policies`. Support optional schema, folder, or target filters in the URL where helpful. Keep `sid` through links, programmatic navigation, and query changes. Put each rendered route inside its providers and render recoverable empty views for missing IDs. Use `withSid()` for internal links that leave the router.
- [x] **Standard sync.** Import `../../templates/state-api.js` unchanged in the Vite config and copy `templates/dataManager.js` unchanged to `src/utils/dataManager.js`. Use `supabase_mock` as the client state namespace. Define fixed defaults in `src/data/seed.js`. Await `loadState(APP, createInitialData)` before mounting routes. Keep one mutation path that commits the full state with `saveState` once per successful business action. Preserve unfamiliar injected fields and handle empty, single-record, large, and partially populated lists. Keep `/go` as the state API's JSON endpoint. Reads, drafts, filter changes, cancel, and idle time produce no mutation.

## P1 — Seed workflows

- [x] **Tables · browse and create.** Offer a searchable table list with a schema filter, then a table detail with Data and Columns views, typed headers, row search, sort, and pagination. From New table, collect schema, name, description, RLS, and editable column definitions. Start with an ID and creation timestamp definition and RLS enabled. Require unique table names per schema and unique column names per table. Saving appends `tables[]` with its `columns[]` and `rlsEnabled`, and an `activity[]` record with action `table.created`.
- [x] **Tables · edit schema and records.** Support table rename and description edits, adding or renaming a column, row insertion, row editing, and confirmed deletion of rows and tables. Use typed inputs, validate required fields and primary-key uniqueness, and preview affected records before deletion. Supply a valid default or backfill when adding a required column to a populated table. Write `tables[].name/description/columns`, `rows[].values` and timestamps as applicable, and `activity[]` with the edited IDs. Remove dependent rows and policies in the same commit when a table is deleted. Keep row links by column ID through a column rename.
- [x] **Authentication · manage project users.** Show email, ID, provider, status, sign-up date, and last sign-in. Offer email or ID search and provider/status filters. Add user opens Create user or Invite user. Validate and normalize email, reject case-insensitive duplicates, and offer confirmation on direct creation. A user detail view supports confirming, banning, unbanning, and confirmed deletion. Write `authUsers[]` with provider, status, and relevant timestamps, plus `activity[]` with the affected user ID. Invitation creates an invited user and records `invitedAt`. The UI reports the recorded invitation. The dashboard operator is already signed in.
- [x] **Storage · manage buckets.** Show bucket name, access type, object count and restrictions. Support name search, a public/private filter, bucket creation, editing access and upload restrictions, and confirmed deletion of empty buckets. Validate names and reject duplicates. Save `buckets[]` with `public`, `maxFileSizeBytes`, and `allowedMimeTypes`, and write `activity[]`. Reject deletion while the bucket contains files or folders and clear policies scoped to a deleted bucket in the same commit.
- [x] **Storage · manage files and folders.** Open a bucket, navigate using folder breadcrumbs, and search by name within the current folder. Create folders, upload through a file picker, download files, rename or move files, and confirm file deletion. Enforce bucket restrictions and unique paths before upload. Use the Harbor `POST /upload` and returned `/files/…` URL for user-chosen binaries. Save object metadata only after the upload succeeds. Seeded file links use original local fixtures. Create or change `objects[]` with `bucketId`, `path`, `kind`, byte size, type, and file URL as applicable. Append `activity[]` for each successful mutation. Navigation and download are reads.
- [x] **Policies · configure row-level access.** Group policies by table or bucket target, with target search and command filters. Expose the table RLS toggle here and on the table detail. New policy takes target, name, command, target roles, and named SQL expressions. Show USING for SELECT/UPDATE/DELETE/ALL and WITH CHECK for INSERT/UPDATE/ALL. Require USING for SELECT/UPDATE/DELETE/ALL and WITH CHECK for INSERT. For UPDATE/ALL, allow omission of WITH CHECK and indicate which expression is then used. Use a read-only statement preview. Support edit and confirmed delete. Write `policies[]` with target IDs, command, roles and expression fields, or `tables[].rlsEnabled` for toggles, plus `activity[]`. Policy expressions are configuration text.
- [x] **Verification.** Implement `SCHEMA.md` with exact record shapes and an Observable State Changes table. Use Playwright from `PILOT_PLAYWRIGHT` with installed Chromium on localhost:5486. Exercise all four workflows through the UI and assert persisted values through `/go?sid=…`, including deletion evidence. Check invalid and canceled actions, deep-link reloads, SID isolation, injected empty/single/large worlds, and an idle tab alongside an active tab under the same SID. Run `npm run build` and record results and changed fields in `TEST.md`. Use gitignored scratch files and launch persistent Vite with an absolute entry point via `Start-Process -WindowStyle Hidden`. The parent runner handles Docker certification and commits.

## Seed data

- [x] Use fixed IDs, ISO timestamps, English text, and synthetic values. Seed 24 tables across three schemas, at least 120 total rows with 30 or more in each of two busy tables, 40 auth users, 24 buckets, at least 90 storage objects, and 32 policies. Use the distribution in the [state model](assets/data_model.md). Exercise useful search results, filters, pagination and empty views in each workflow.

## Scope

The application models a local project administrator's workflows. Login, credentials, email delivery, production APIs, live Postgres or policy evaluation, billing, and deployment are outside this phase.
